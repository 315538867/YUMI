# v2-data-lifecycle Specification

## Purpose
为 YUMI V2 提供与 V1 测试数据物理隔离的本机数据空间，使正式业务从空库开始录入，同时保证附件、备份、恢复和审计始终指向同一套 V2 事实。
## Requirements
### Requirement: V2 独立数据空间

系统 SHALL 使用独立的 V2 数据库文件、附件目录和备份目录保存 V2 业务数据。首次启用 V2 时系统 MUST 创建空的 V2 存储，且不得读取、迁移、修改或删除 V1 业务数据库及其附件。

#### Scenario: 首次启动 V2

- **WHEN** 管理员在仍保留 V1 测试数据库的设备上首次启动 V2
- **THEN** 系统创建并打开空的 V2 数据空间，V1 数据文件和附件目录保持不变

### Requirement: V2 存储范围一致性

系统 MUST 使 V2 数据库、业务附件、备份元数据和恢复目标使用同一套 V2 存储配置。涉及 V2 数据与附件关联的业务写入 SHALL 原子完成，失败时不得产生指向不存在附件的业务记录。

#### Scenario: V2 收款凭证保存失败

- **WHEN** 管理员保存一笔带凭证的订单收款且附件写入失败
- **THEN** 系统不保存该收款流水及其附件关联，并返回可识别的失败信息

### Requirement: V2 数据库版本校验

系统 MUST 在打开 V2 数据库时校验其 schema 版本，仅执行面向 V2 schema 的增量迁移。系统不得将 V1 表结构识别为 V2 已初始化状态。

#### Scenario: V2 数据库缺少新版本结构

- **WHEN** 系统打开一个较早版本的 V2 数据库
- **THEN** 系统按 V2 迁移序列升级并记录版本，既有 V2 业务事实保持可读取
