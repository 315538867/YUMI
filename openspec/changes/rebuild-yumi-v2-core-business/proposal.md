# YUMI V2 核心业务重构提案

- 提案名称：YUMI V2 核心业务重构
- Change ID：`rebuild-yumi-v2-core-business`
- 关联方案：`docs/solutions/2026-09-07-yumi-v2-core-business-reconstruction-solution.md`（v2.1）
- 状态：实施中（阶段 A；A.1 至 A.3 已完成）
- 创建人：Codex
- 创建时间：2026-09-07
- 实施方式：单一提案，内部按阶段 A 至 E 顺序执行；阶段完成不另建提案

## Why

YUMI 当前的 V1 订单、排班、制作、工资报表和成本逻辑围绕测试数据、单体服务与单一页面构建，无法准确表达定制捏捏工作室的多工序数量流转、次日质检、不合格扣款、负责人最终工资决定、分批发货、弹性售后和按实际收付款日期统计的财务事实。用户已确认不迁移 V1 测试数据，需以 V2 重建真实业务基础，并在同一份提案中保持全链路契约和任务依赖一致。

## What Changes

- **BREAKING**：应用启动改为使用独立的 `yumi-studio-v2.sqlite`、`attachments-v2` 和 V2 备份空间；不读取、迁移、修改或删除 V1 测试业务数据。
- 重建客户、商品、订单、订单商品快照、订单金额调整、订单内容变更、订单收退款、分批发货和轻量售后；订单金额、订单内容、订单资金和订单核算成本保持分离且可追溯。
- 实现制作、捏毛装袋、打包、发货四道固定工序的工作安排、任务、完成申报、次日质检、履约数量事件、期初在制品、返工和售后补发；不提供可配置流程引擎。
- 实现兼职工资结算：排班口径与考勤口径两套参考金额、制作/捏毛提成、制作胶水扣款、捏毛计划分钟扣款、扣款顺延、负责人最终实发和确认即记工资支出。
- 扩展统一 `financial_entries` 为真实现金事实，增加动态收支类目、日常收支、私人垫付、整笔报销和按实际收付款日期统计的月度财务首页；日常支出不关联订单。
- 将主进程按领域拆分为 domain、repository、service、IPC，拆分共享契约与 preload，并将渲染层拆为应用壳、领域页面、composable 和无 IPC 直连的组件。
- 重建订单、履约、工资和月度经营报表与导出；在全部 V2 能力验证后，清理或隔离 V1 入口、类型、测试和页面。

## 实施阶段与依赖

| 阶段 | 目标 | 依赖 | 阶段完成条件 |
| --- | --- | --- | --- |
| A | V2 数据基线、共享契约、基础资料、订单金额/资金、分批发货 | 无 | 能在独立 V2 空库完成建单、多笔收退款、金额调整、内容变更和不超确认数量的发货 |
| B | 多工序履约、期初在制品、质检、返工、售后补发 | A 的订单与订单商品 | 订单商品能在固定四工序中按质检确认数量流转，发货上限收紧为待发货数量 |
| C | 兼职工资结算与扣款顺延 | B 的任务、质检、扣款依据；A 的资金流水 | 能生成两套参考工资、记录负责人实发、顺延扣款并只产生一笔工资支出 |
| D | 日常财务、垫付报销、财务首页与售后单 | A 的资金流水；C 的工资来源 | 能按实际付款日统计收入/经营支出/经营结果/待报销，且报销不重复计入经营支出 |
| E | 报表、导出与 V1 收敛 | A 至 D | 所有 V2 报表与导出基于统一事实，V1 入口不再影响 V2 正式业务 |

每个阶段必须完成其任务、定向测试与回归验证，才能开始下一阶段；它们均属于本提案，不创建独立阶段提案。

## Capabilities

### New Capabilities

- `v2-data-lifecycle`: V2 独立数据库、附件、备份、恢复和审计的数据生命周期。
- `order-fund-ledger`: 订单收款、退款、售后收费的统一资金事实、日期口径、冲正规则与汇总。
- `order-change-history`: 订单金额调整及订单内容变化的可追溯历史。
- `multi-process-fulfillment`: 固定四工序的工作安排、任务、完成、质检、数量流转、期初在制品、返工和补发。
- `worker-settlement-management`: 兼职工资两种参考口径、不合格扣款、顺延、负责人实发和确认记账。
- `studio-finance-management`: 日常收支、动态类目、私人垫付、整笔报销和月度经营汇总。
- `after-sales-management`: 负责人决定的轻量售后记录、收费、核算成本、补发或重新处理。

### Modified Capabilities

- `order-and-payment-management`: 切换至 V2 订单金额/资金/履约数量/分批发货模型。
- `product-catalog-and-costing`: 商品与订单商品快照支持制作提成、胶水扣款、材料/包装/配饰成本及订单核算成本口径。
- `production-scheduling`: 由固定上下班时间的制作排班改为按日期、人员、工序、任务数量和计划分钟的工作安排。
- `local-data-and-backup`: 本地存储、附件、备份、恢复、审计和导出切换至 V2 数据空间。
- `studio-reporting`: 按 V2 订单资金、履约、工资与财务事实重建报表和导出。

## Impact

- 数据库：新建独立 V2 schema、迁移序列和领域事实表，不对 V1 文件执行破坏性迁移。
- 主进程：拆分订单、履约、结算、财务领域的纯计算、仓储、服务和 IPC；所有跨表确认以 SQLite 事务保证。
- 共享契约与 preload：由单一 `src/shared/contracts.ts` 拆为领域契约并拼装 `YumiApi`。
- 渲染层：`app.tsx` 收敛为应用壳，订单、履约、工作安排、工资、财务、基础资料、报表和设置按页面/composable/组件拆分。
- 测试：新增领域、仓储服务、IPC、渲染和端到端测试；每个阶段执行质量门禁，阶段 E 后有意清理 V1 测试与旧实现。
