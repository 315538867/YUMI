## Why

当前版本保留了客户、商品、订单、收退款、发货、履约、兼职人员、工资、报表和备份恢复等模块，但相较 V1，订单金额、订单级缝边、订单表、发货清单、查看优先交互、自动关闭通知以及部分经营分析能力仍缺失或退化。尤其是“初始确认金额”和商品级缝边收费无法表达真实业务，继续使用会影响收款、成本、履约和历史单据。

本提案将此前确认的需求作为一个整体，使用一个提案、一个实施任务清单，按依赖关系分阶段推进；不把关联能力拆成互相重复的多个提案。

## What Changes

- **BREAKING** 移除新订单中的“初始确认金额”输入，订单金额改为由订单商品明细自动计算。
- 将缝边选择、缝边数量和缝边单价落实到每个订单商品明细；勾选后默认全量，允许修改为部分数量。
- 增加订单级优惠和明细级优惠，并统一订单金额、调整后应收、已收净额和待收金额口径。
- **BREAKING** 商品资料不再保存客户缝边售价；如成本核算需要，只保留明确命名的内部缝边成本。
- 统一页面为查看优先：默认只读，点击“新增”或“编辑”后才进入编辑态，保存成功回到只读态。
- 统一右上角全局通知；成功/信息通知自动关闭，字段错误和保存失败仍在当前表单上下文展示。
- 恢复独立订单表和发货清单导出，并支持合并 XLSX、图片、打印设置、全部订单商品、发货数量列和历史发货批次快照。
- 恢复预留天数、制作截止日期、商品材料/损耗/模具产能、客户订单历史/统计、产能风险报表、交期风险报表和部分收款凭证入口。
- 不做旧 V2 数据迁移，不读取旧 `initialConfirmedAmountCents` 作为新订单金额，不把旧 `edgeCostCents` 转换为客户售价；新模型直接初始化本地数据和测试夹具。

## Capabilities

### New Capabilities

- `notification-feedback`: 全局通知位置、自动关闭、堆叠和错误分流规范。
- `customer-order-insights`: 客户历史订单与客户聚合统计。
- `capacity-and-delivery-risk`: 商品产能风险与订单交期风险分析。

### Modified Capabilities

- `order-and-payment-management`: 订单明细缝边、优惠、自动金额、预留天数和制作截止日期。
- `order-change-history`: 金额调整基于订单明细计算金额，不再基于孤立初始金额。
- `product-catalog-and-costing`: 材料/损耗/模具产能及内部缝边成本，移除客户缝边收费。
- `operational-ui-flow`: 所有维护页面默认只读、显式进入新增/编辑。
- `detail-workspaces`: 订单详情查看态与编辑态分离。
- `shipping-document-generation`: 独立订单表/发货清单、完整金额与批次快照。
- `studio-reporting`: 客户统计、产能风险和交期风险报表。
- `order-fund-ledger`: 部分收款凭证的关联和查看。

## Impact

影响订单、商品、客户、资金、履约、报表和导出相关的契约、领域计算、仓储、服务及 renderer 页面。需要更新本地数据库初始化 schema 和测试夹具，但不新增旧数据转换层，不引入第三方依赖。
