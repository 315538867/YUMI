## Context

当前样式集中在 `src/renderer/styles/app.css`，其中 `.content`、`.stat-grid`、`.stat`、`.panel`、`.form-section`、`.order-summary-bar`、`.queue-item` 和 `.report-filters` 使用了较大间距或卡片外框。详见 `proposal.md` 的动机和 `docs/solutions/2026-09-05-yumi-desktop-surface-layout-refinement.md` 的视觉规则。

## Goals / Non-Goals

**Goals:**

- 在不改变页面结构和业务流程的前提下，把常规工作区从边框卡片收敛为柔和底色分区。
- 统一统计、面板、表单、汇总、队列和报表筛选的紧凑密度。
- 保留表格、日历和表单的可操作边界及键盘焦点反馈。
- 以可执行的静态样式契约测试防止关键选择器回退到边框卡片风格。

**Non-Goals:**

- 不改动任何 SQLite 数据、订单成本、收付款、排班或产能计算。
- 不重构 React 组件、不替换 Radix Themes、不引入新的设计系统依赖。
- 不删除日历网格、表格行分隔、输入控件边框或 `:focus-visible` 轮廓。
- 不针对不同屏幕尺寸重新设计布局断点。

## Decisions

### 以三层中性色面表达层级

页面底色保持暖灰，常规内容面使用偏白暖灰，次级区域使用略深的暖灰；面之间通过 8px 圆角和 8–12px 紧凑间距区分。相较于继续使用 1px 外框，这能减少网页卡片感，并与既有暖色主题保持一致。

备选方案是使用更强的色块或全面取消圆角。前者会削弱克制感，后者会让表单与密集数据区缺少可扫描分组，因此不采用。

### 语义状态采用低饱和背景

`.stat.warning`、`.stat.danger` 以及风险待办项将以淡杏、淡红等背景表达状态，不保留顶部或左侧强调边线。文字和现有徽标仍保留，避免仅依靠颜色传递状态。

备选方案是保留强调边线并仅收紧间距；这不符合“避免用边框区分板块”的已确认方向，因此不采用。

### 保留数据定位线和交互轮廓

日历与表格内部的网格线、行分隔线，以及输入控件和 `:focus-visible` 轮廓不纳入去边框范围。它们不是模块外框，而是定位、编辑与键盘可访问性的必要反馈。

### 样式契约测试使用源文件断言

项目现有组件声明测试通过读取源码检查回归；本次新增 `tests/desktop-surface-layout.test.ts`，断言关键选择器具有无外框、无卡片阴影和紧凑间距的样式声明，并断言日历网格与焦点轮廓仍存在。视觉样式无法由 jsdom 可靠地端到端测量，源文件断言能够在不引入浏览器测试依赖的情况下锁定设计约束。

## Risks / Trade-offs

- [低对比度面色可能让区块边界不够明显] → 保持 8px 圆角、清晰分组标题与 8–12px 留白，并只在需要数据定位的组件中保留细线。
- [一次性移除过多边框可能影响表单阅读] → 仅移除常规业务容器外框；输入控件、行分隔与日历网格不变。
- [静态测试不等同真实截图] → 使用明确选择器契约，同时在实施后启动桌面应用进行人工界面检查。

## Migration Plan

1. 先新增会失败的样式契约测试，锁定最终的紧凑间距、无外框和保留操作边界规则。
2. 仅修改 `src/renderer/styles/app.css` 中常规业务容器和状态容器的声明。
3. 运行定向测试、完整测试、类型检查、Lint、构建，并启动 Electron 检查概览、订单、排班、商品和报表页面。
4. 若出现对比度、可读性或布局回归，回滚本次 CSS 选择器修改即可；不涉及数据迁移。
