- 提案名称：订单、排班与兼职人员数据联动

- 方案版本：v1.0
- 状态：已实施，待归档
- 创建人：Codex

- 关联方案：`docs/solutions/2026-09-06-order-schedule-worker-linkage-solution.md`

## Why

订单、排班和兼职人员目前虽然已有底层关联，但页面上的生产状态和数量没有统一汇总，无法在订单中直接判断已排、未排、合格完成和待补排，也无法从兼职人员反查其订单任务。订单交付目标是合格品，因此不合格品、缺勤或取消班次造成的缺口必须被明确识别；现在需要把这套口径落实到已有页面和排班保存流程中。

## What Changes

- 为订单商品和订单增加实时计算的排产进度：订单需求、有效已排、合格完成、不合格累计、未排/待补排和排产状态。
- 在订单列表和订单详情展示合格生产进度、待补排风险及相关排班、兼职人员和完成结果。
- 在兼职人员详情增加按订单/商品汇总的任务视图，支持反查订单和班次。
- 在排班创建与编辑时展示订单商品当前缺口；若本次安排会超出订单合格品需求，必须先确认明确的超排风险才能保存。
- 将请假、缺勤、取消班次释放的计划量，以及完成班次中合格数量不足造成的差额，实时反映为订单未排/待补排。
- 继续保留现有收款、发货、人员结算和内部生产状态字段的业务口径；新增排产状态作为订单生产进度的只读展示。
- 不新增排产进度冗余表或持久化汇总字段，不自动分配日期和兼职人员。

## Capabilities

### New Capabilities

### Modified Capabilities

- `order-and-payment-management`：订单流程页面新增合格品生产进度、排产状态及相关排班展示，同时保持收款和发货状态独立。
- `production-scheduling`：排班数量需要按订单商品合格品需求实时汇总，缺勤/取消释放缺口，超出订单需求时增加确认风险，并向订单和兼职人员提供关联任务数据。

## Impact

- 共享契约：扩展订单摘要、订单商品详情、订单详情、兼职人员详情和排班预览返回值。
- 主进程服务与仓储：增加订单商品生产进度、订单相关排班和人员订单任务的聚合查询，统一状态计算规则。
- React 渲染层：修改订单列表、订单详情、排班表单、兼职人员详情及对应跳转和展示测试。
- SQLite：复用现有 `orders`、`order_items`、`shifts`、`shift_tasks`、`workers` 关联，不需要数据库迁移。
- 测试：补充领域/服务聚合、状态转换、超排确认、页面展示和端到端联动测试。

## 实际实施记录（2026-09-06）

- 已新增以合格品为口径的订单商品/订单排产进度：合格数、不合格累计、待执行已排量、未排量、超排量和独立排产状态；原有 `productionStatus`、收款、发货和人员结算口径未改变。
- 已通过既有 `order_items`、`shift_tasks`、`shifts`、`workers` 事实表实时聚合订单关联排班与人员订单任务，未新增数据库迁移或进度冗余表。
- 已在排班预览中返回订单商品的当前进度；新增 `ORDER_QUANTITY_EXCEEDED` 风险，携带订单号、商品、订单量、已合格量、既有已排量、本次计划量和超排量。未确认风险不能保存，确认后沿用既有风险记录保存。
- 已在订单列表/详情展示排产状态和合格、已排、未排数据；订单详情展示关联班次的计划、合格、不合格、未完成和班次入口。兼职人员详情展示订单任务并可分别跳转订单和班次。
- 验证完成：定向 32 项测试通过；`npm run typecheck`、`npm run lint`、全量 `npm test`（28 文件、81 测试）和 `npm run build` 通过；`openspec validate order-schedule-worker-linkage --strict` 通过。
