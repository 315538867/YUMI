# 新增独立客户管理

## Why

当前订单编辑页既承担客户资料录入，又会在未选择客户时自动创建客户档案。这样会把一次性订单信息与客户主数据混在一起，无法集中维护客户，也无法明确客户与订单之间的关联关系。

需要将客户管理独立出来：客户资料只在客户管理中维护；订单只能关联已有客户，同时仍可保存本单独立的收货信息快照。

## What Changes

- 新增独立的客户管理入口、客户列表、客户新增编辑和客户详情，集中维护客户名称、联系方式、默认收货地址及备注。
- 在客户详情中展示仅属于该客户的订单数量、待发货数量、当前未结清金额及关联订单历史。
- 对已有订单的客户禁止删除；没有关联订单的客户允许删除。
- 调整订单新建与编辑：必须选择已有客户，选择后带入客户资料；订单内修改的名称、联系方式和收货地址仅更新本订单快照，不回写客户主档。
- 停止根据订单手填资料自动创建客户档案。

## Capabilities

### New Capabilities

- `customer-management`: 提供客户主档的独立维护、客户详情汇总、关联订单查询和受订单关联约束的删除能力。

### Modified Capabilities

- `order-and-payment-management`: 订单创建和编辑改为必须关联既有客户，并保留订单级客户信息快照与客户主档相互独立的行为。

## Impact

- 影响共享 contracts 中的客户管理和订单客户输入输出模型。
- 影响 SQLite 仓储、服务层校验、IPC 与 preload 的客户接口。
- 影响订单编辑器的客户选择与保存校验，并新增客户管理页面入口和页面组件。
- 影响订单管理与客户管理自动化测试。
- 本次不修改数据库表结构；现有历史订单及其客户快照继续保留。
