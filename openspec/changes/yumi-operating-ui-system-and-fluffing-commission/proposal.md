## Why

当前经营页面已具备订单优惠、分批发货快照、订单/资金/售后等真实业务能力，但视觉规则仍分散在页面中，订单详情的信息层级、操作归属和各模块的呈现密度不一致；静态设计目录也尚未成为可落地的组件规范。与此同时，商品已能维护制作提成，却不能维护并冻结商品级“捏毛装袋提成”，导致捏毛工资仍依赖统一费率，不能准确反映不同商品的计件事实。

## What Changes

- 将已确认的全量经营界面目录转化为可复用的浅色经营设计系统：建立语义化颜色、排版、间距、圆角、阴影、状态与布局令牌，并以统一组件承载标题、标签、指标、列表、表单、详情、快照提示和动作区。
- 按真实现有功能重构应用壳及工作台、订单、排班、工资、财务、报表、客户、商品、设置页面；不新增脱离现有领域模型的业务功能，列表默认可扫描、详情默认只读、编辑和新建通过明确入口进入。设置页新增“计算公式”标签，集中列出当前实现的业务计算、输入来源、快照边界和明确排除项，且不允许在该页虚构或编辑口径。
- 调整订单详情工作区：头部以客户/订单关键信息为主、订单号降为辅助元信息；标签固定为“概览 / 排班 / 发货 / 资金 / 盈利 / 售后”；概览只显示排班摘要，完整排班在独立标签中处理；所有当前可执行的订单级动作显式展示，不以“更多”隐藏。
- 在每条发货批次记录中提供“查看发货清单”和“导出本批清单”，让界面直接展示由该批次快照生成的清单内容；已存在的 XLSX 导出和历史快照规则保持不变。
- 为商品新增“捏毛装袋提成（元/件）”，在商品、订单商品快照、排班任务、质检扣款和兼职工资结算中端到端使用该商品的冻结费率；制作提成与捏毛装袋提成分开显示和计算。包装成本继续是商品成本，不在本次变更中虚构为打包计件提成。
- 保留已实现的订单优惠金额、订单商品折扣、订单/发货清单导出、发货批次作废和批次快照；本变更只将它们纳入统一的视觉和回归验证，不重复改造其既有事实链路。
- 将“目录存在”与“真实页面还原”分开验收：以目录中的 40 个屏幕为逐页视觉基准，真实 React 页面必须逐一还原信息层级、版式、动作位置、密度和抽屉/确认态；通用组件接入或静态目录渲染均不能替代该验收。

## Capabilities

### New Capabilities

- 无。

### Modified Capabilities

- `operating-ui-design-system`: 将现有页面动作与标签命名规则扩展为可访问的语义令牌、组件契约、密度与页面状态规范，并规定设置中的计算公式目录必须源自当前已实现的领域计算。
- `detail-workspaces`: 扩展订单详情为客户优先的紧凑头部，并增加排班与盈利工作区标签及明确的动作展示规则。
- `shipping-document-generation`: 在不改变批次快照和导出的前提下，支持按已保存发货批次查看清单预览。
- `product-catalog-and-costing`: 在商品参数和订单商品快照中增加捏毛装袋单件提成。
- `worker-settlement-management`: 以订单商品快照中的捏毛装袋提成计算合格计件与不合格扣款，替换统一捏毛提成口径。

## Impact

- **前端：** `src/renderer/styles/`、`src/renderer/components/ui/`、应用壳和各业务页，以及页面/组件测试；以现有完整设计目录作为视觉验收参考。
- **共享契约与预加载：** `src/shared/contracts/products.ts`、`fulfillment.ts`、`reports.ts`、`v2-api.ts` 与 `src/preload/index.ts`，新增商品提成字段及发货清单预览读取能力。
- **主进程与本地 SQLite：** `src/main/database/v2-migrations.ts`、商品仓储/订单服务/排班服务/结算服务/报表 IPC；新增产品列、将费率写入订单快照和任务费率快照，并只读返回既有发货批次快照。
- **兼容性：** 旧商品和旧订单快照以 0 元捏毛装袋提成兼容；旧发货批次的快照仍为预览和导出的唯一数据来源。无外部网络 API 或第三方依赖变更。
