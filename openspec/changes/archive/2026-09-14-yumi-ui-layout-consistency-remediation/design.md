## Context

见 `proposal.md`。真实 Electron 审阅已定位到三类共享层问题：列表工具栏将多个筛选条件视为一个不透明节点，排班表格把同一工序拆成卡片堆叠，期初在制品缺少候选结果与步骤容器样式；同时，部分长详情继续由窄抽屉承载，造成表格折断和底部动作错位。当前代码已具备 `YumiPageHeader`、`YumiSection`、`YumiListToolbar`、`YumiListSurface` 等共享入口，故本变更以补足这些入口的布局契约为主，而不是重写业务页面。

## Goals / Non-Goals

**Goals:**

- 将导航、标题上下文、页面级 Tab、页面/区块/记录动作的空间归属做成共享约束。
- 将列表工具栏、多工序任务分配、分步工作区与客户长详情分别改为可测的紧凑结构。
- 保持已有 renderer 服务调用、领域数据和业务操作不变，并以单元/页面测试和真实 Electron 复核作为完成证据。

**Non-Goals:**

- 不重新设计经营颜色主题，不添加新业务字段、接口、计算公式或权限。
- 不将所有抽屉一律替换为页面；短编辑、确认和补充仍保留抽屉或 Dialog。
- 不以静态设计图替代真实 Electron 的交互和视口验证。

## Decisions

### 1. 页头提供独立导航上下文，右侧仅保留页面动作

为 `YumiPageHeader` 增加可选的导航上下文插槽或配套共享导航行，返回按钮由共享 ghost 样式渲染在标题上方/左侧。标题继续使用 `title + meta + description`，但页面调用须将客户、状态、日期、编号等真实信息放进标题或元信息；说明只保留能帮助决策的范围信息。与当前任务直接相关的高频页头动作必须全部可见，不得用“更多”隐藏；菜单只保留低频且不影响主流程的操作。

**备选方案：** 将返回继续建模为 `secondaryAction`。未采用，因为它仍会与导出、编辑等业务动作并列，无法表达导航层级。

### 2. 工具栏以“独立筛选槽位”而不是一个筛选节点布局

`YumiListToolbar` 将把筛选内容标准化为单个筛选项容器。桌面端用稳定的 flex/grid 组合：搜索占用可用余宽，筛选项采用受控宽度，统计不收缩；在 1024px 以下才允许控件折行，在 640px 以下再转全宽单列。保留现有 `filters` 调用兼容性，并展开 Fragment/数组，避免一次迁移所有页面。

**备选方案：** 只在订单页面另写 CSS。未采用，因为其他列表同样会再次出现筛选堆叠，无法形成系统规范。

### 3. 排班工序为单行汇总，任务详情进入既有处理上下文

订单视角每个工序只渲染一条 `任务分配` 行。已派数量按有效任务聚合；一项任务时显示人员和数量，多项任务时显示人数和汇总数量；未派和超派分开表达。行尾仅显示“派工”或“查看任务”等适用入口，沿用现有派工 Dialog 与任务处理入口，不在单元格中复制详情卡片。

**备选方案：** 将每项任务继续作为卡片但缩小。未采用，因为根因是信息颗粒度与表格单元格不匹配，缩小卡片仍会纵向膨胀。

### 4. 期初在制品以统一工作流步骤和候选行呈现

第一步与第二步均由同一工作流表面容器承载；候选结果使用有边界的紧凑行，并显式表达选中态。返回排班队列使用页头导航上下文，提交仍留在第二步表单内。该结构只改变呈现，不改变候选查询、选择、登记请求或数据归属。

### 5. 长详情迁移到主工作区，短操作保留抽屉

客户资料等包含统计和订单表格的读取态改由主工作区详情承载，并复用统一返回上下文；编辑客户保留为短单目的抽屉或由详情页发起。迁移先补充页面测试，确保从列表进入、返回列表、编辑和订单跳转的已有行为不丢失。

**备选方案：** 扩大抽屉宽度。未采用，因为多列表格、统计和页脚动作仍会在中等屏幕失去稳定性。

## Risks / Trade-offs

- [共享工具栏展开 Fragment 可能影响现有筛选调用] → 为单项、数组和 Fragment 添加组件测试，并回归订单及其他代表性列表页面。
- [客户详情迁移可能影响既有侧栏操作路径] → 先测试列表进入、返回、编辑与订单跳转，再保留编辑入口的可访问名称。
- [排班汇总可能错误包含历史任务] → 继续复用已有的有效任务聚合函数，并以待完成/待质检、超派测试覆盖。
- [桌面布局在窄屏回归] → CSS 只在明确断点降低为换行/单列，并在真实 Electron 中分别检查 1440px 与窄宽度。
- [已有业务能力或桥接 API 在真实页面中缺失] → 先核对 renderer、preload/bridge、服务和 contract 的调用链；若确需后端/IPC 改动，先把独立变更和验收条件补入 OpenSpec，再实施，禁止用前端占位掩盖。

## Migration Plan

1. 先记录当前真实截图问题并补失败测试，建立共享组件和三处代表页面的回归边界。
2. 依次实现页头导航/工具栏、排班任务分配、期初在制品工作区、客户长详情迁移；每一步运行受影响测试。
3. 在用户已运行的本地 Electron 中复核工具栏、排班、期初在制品、客户详情与订单详情的动作/Tab/抽屉边界；发现运行时错误时按调用链定位，不使用 UI 降级掩盖。
4. 完成全量测试、类型检查、Lint、格式检查、OpenSpec 严格校验与差异检查后，再更新任务状态；若需要回退，可按独立的共享组件、页面迁移提交分段回退。
