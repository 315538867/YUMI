# 长详情与抽屉承载审查

审查日期：2026-09-14

## 口径

- **主工作区详情**：读取态包含多 Tab、历史记录表格或多个独立业务区块；页面标题和返回导航承载对象上下文。
- **抽屉**：只承接目的单一、关闭路径明确的新增、编辑、确认、作废或少量资料查看；不把订单历史、资金明细等长读取态塞入窄容器。

| 业务对象  | 当前读取态与入口                                                                                                        | 保留的抽屉入口                                                                    | 结论                                                                     |
| --------- | ----------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| 订单      | 订单列表“查看详情”进入 `workspaceMode === 'detail'`；页头、返回导航与概览/排班/发货/资金/盈利/售后 Tab 均位于主工作区。 | 新建订单、订单内容编辑、分批发货、作废发货、收款与快捷建档仍为目的单一操作。      | 长读取态已在主工作区；不回迁抽屉。                                       |
| 客户      | 客户列表“查看详情”进入客户主工作区，页头显示客户名与返回导航；基础资料、订单统计和客户历史订单表同屏读取。              | 新建/编辑客户使用 `YumiSheet`；从详情点击编辑后，取消或放弃修改回到同一客户详情。 | 长读取态迁出窄抽屉；编辑仍保留抽屉。                                     |
| 商品      | 商品列表“查看详情”打开只含基础资料及制作/成本参数的分组读取态。                                                         | 商品新建、编辑使用 `YumiSheet`。                                                  | 当前没有历史表格或多 Tab；保留为有界资料查看抽屉，不与客户详情强行同化。 |
| 工资结算  | 工资结算“查看详情”在页面主内容区展示 `SettlementDetail`，保留结算说明、计算结果与确认上下文。                           | 新建结算草稿、待退款处理使用 `YumiSheet`。                                        | 读取态不回迁抽屉；短操作继续使用抽屉。                                   |
| 收支/垫付 | 收支记录以页面列表承载；报销选择、收支登记等操作由抽屉确认。                                                            | 收支登记、批量报销确认使用 `YumiSheet`。                                          | 维持列表读取与短操作抽屉的分界。                                         |

## 客户历史订单布局结论

客户详情中的“客户历史订单”保留横向滚动兜底，并对订单号、日期、金额、状态和操作列定义最小宽度与不换行规则。窄屏时优先横向查看完整记录，不逐字挤压联系人、地址、订单号和操作入口。
