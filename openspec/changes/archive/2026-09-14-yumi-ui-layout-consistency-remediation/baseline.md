## 业务能力保留点

以下能力属于真实实现的一部分，后续布局修改只能调整承载和入口位置，不能删除、改名或用静态占位替代：

- 新建订单中的优惠金额、缝边/定制化服务、商品工序和费用字段。
- 订单详情六个 Tab：概览、排班、发货、资金、盈利、售后。
- 发货记录新增、运费承担方、发货清单下载，以及下载内容基于发货时快照而不是后续订单编辑结果。
- 商品工序：制作、捏毛装袋、打包；可指派人员来自排班数据。
- 人工成本、捏毛提成、提成/工资和盈利计算；兼职人工时薪为统一参数时按现有公式读取。
- 设置中的计算公式 Tab 与已有公式展示/维护入口。
- 期初在制品登记归属已有订单商品，不创建新订单，不产生独立库存副作用。

## 基线结论

1. 页面级 Tab 属于页面骨架，应位于页头之后、首个内容区之前；订单详情、排班视角、工资、设置等不应将 Tab 放在内容中间。
2. 页面级动作属于页头右侧；返回属于独立 navigation，不与业务动作混在同一 group。
3. 长读取态和多 Tab 内容使用主工作区；短编辑/确认操作保留现有抽屉或对话框，不能因样式统一把长详情改回窄抽屉。
4. 本次变更的首要回归边界是布局、间距、承载和语义；业务数据、字段、接口、公式、快照语义和已有操作路径不在允许修改范围内。

### 保护范围

以下内容不属于本变更的自由修改范围：

- 业务字段及业务含义：订单优惠、缝边/定制化服务、制作/捏毛装袋/打包工序、运费字段（如后端已有）、工资、提成与盈利字段。
- renderer → preload/bridge → IPC → service → repository → contract 的接口、参数、返回值和错误语义。
- 计算公式及其边界：商品成本不含运费；人工成本、制作提成、捏毛提成按当前公式和快照口径计算；统一兼职时薪按现有设置读取。
- 数据归属、订单商品阶段流转、发货记录与发货清单快照语义；后续编辑订单不得改写已生成的发货清单快照。
- 已存在的创建、编辑、派工、发货、下载、退款、结算、返回和 Tab 切换操作路径。

### 例外与阻断规则

- 客户详情读取态允许由抽屉迁移到主工作区，这是本变更明确批准的承载例外；编辑态不随之迁移。
- 如果某项设计需要新增或修改 API、preload/bridge、IPC、service、repository、数据库迁移或 contract，必须先记录为后端能力项并停止该项 UI 假实现；不得用静态数据、猜测字段或临时 mock 冒充真实功能。
- 如果真实运行环境与源码能力不一致，记录运行时版本/构建产物问题，不能通过删除入口或隐藏错误来“完成”任务。

用户提供的真实运行截图曾出现：`window.yumiV2.reports.getOrderBusinessDetail is not a function`。源码审计显示该方法同时存在于 renderer composable、preload、IPC、service 和 contract，因此当前更符合“正在运行的 Electron preload/构建产物未刷新或版本不一致”，而不是源码缺少 API。由于不能擅自重启用户正在使用的本地调试环境，本提案只记录该异常；真实 Electron 刷新后的验收仍是后续 0.3/V9 和 7.x 的独立证据。
