# 用户可见状态中文化设计

- 关联提案：`openspec/changes/localize-user-visible-statuses/proposal.md`
- 方案版本：v1.0
- 状态：拟实施
- 创建人：Codex
- 创建时间：2026-09-06
- 最后修改时间：2026-09-06

## Context

现有渲染页面在 `app.tsx` 内部分别维护生产、财务和排班状态的中文映射。映射分散，订单详情至少有一处直接渲染生产状态；排班映射在未识别值时直接回传英文枚举。详见提案与 `user-visible-status-localization` 能力规范。

## Goals / Non-Goals

**Goals:**

- 在渲染层提供唯一的状态展示入口，覆盖生产、财务和排班三种状态。
- 让所有用户可见的状态标签、文本、下拉选项和报表列复用同一中文名称与颜色语义。
- 对未知值提供稳定的中文兜底，同时不阻断历史记录页面的加载。

**Non-Goals:**

- 不变更数据库、共享契约或 IPC 中的英文枚举。
- 不修改状态机、状态流转、筛选入参和存量数据。
- 不进行多语言国际化框架建设；本次仅定义中文界面展示。

## Decisions

### 决策：在渲染层抽取独立状态展示模块

创建一个与页面组件分离的纯函数模块，接收内部枚举或字符串并返回中文名称及状态色。`app.tsx` 不再保留分散的映射表，也不直接渲染原始状态字段。

- **理由**：保证订单、报表和排班入口使用同一词典，单元测试可不依赖完整页面。
- **备选方案：逐处替换文本。** 不采用，因为后续新增展示点容易遗漏，且未知值回退逻辑会重复。

### 决策：未知值显示“未知状态（原始值）”

展示函数对任何非预期字符串返回带中文前缀的兜底名称，保留原始值以协助数据诊断；色彩使用中性灰。

- **理由**：满足中文可读性，也不掩盖异常数据。
- **备选方案：只显示“未知状态”。** 不采用，因为排查历史数据时会丢失关键信息。

### 决策：下拉选项以受类型约束的已知枚举生成

状态更新控件继续提交内部英文枚举作为 `value`，仅将 option 文本改为展示模块输出的中文名称；未知值不会作为可选流转状态插入下拉框。

- **理由**：保持现有服务校验与状态流转兼容，避免把未知状态引入写入路径。

## Risks / Trade-offs

- [遗漏状态展示点] → 通过全仓库检索原始状态字段、页面源码断言和人工开发窗口检查覆盖列表、详情、报表、日历与下拉框。
- [未来新增枚举尚未配置中文名称] → 统一兜底显示“未知状态（原始值）”，并在模块测试中锁定该行为。
- [状态颜色出现差异] → 将颜色与名称同时由集中模块返回，页面不再独立判断已知状态颜色。

## Migration Plan

1. 新增渲染层状态展示模块与单元测试，不改持久化结构。
2. 将页面中的直接状态渲染、局部名称映射和颜色判断迁移至该模块。
3. 运行类型检查、静态检查、全量测试、构建和 OpenSpec 严格校验。
4. 如需回滚，仅还原渲染层模块与页面调用；已有数据库记录和接口无需迁移或回滚。
