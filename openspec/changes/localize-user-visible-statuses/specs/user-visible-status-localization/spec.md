## Purpose

确保工作室管理应用中所有面向用户展示的订单、收付款和排班状态均使用一致的中文表达，在兼容历史数据和未来枚举扩展的同时避免暴露内部英文状态码。

## ADDED Requirements

### Requirement: 已知业务状态的统一中文展示

系统 SHALL 为订单生产状态、订单收付款状态和排班状态的每个已支持枚举提供唯一、统一的中文名称。列表、详情、概览、报表、日历卡片、状态标签和状态下拉选择项 MUST 使用该中文名称，而不得直接显示英文内部枚举。

#### Scenario: 在订单与报表中查看状态

- **WHEN** 管理员查看任一订单详情、订单列表、概览或订单报表
- **THEN** 系统以中文显示该订单的生产状态和资金状态

#### Scenario: 在排班工作区查看或变更状态

- **WHEN** 管理员查看排班日历、排班详情或打开排班状态下拉选择项
- **THEN** 系统以中文显示当前状态及全部可选状态

### Requirement: 未识别状态的中文安全兜底

系统 MUST 为未识别的历史状态或未来扩展状态提供中文兜底展示，并在兜底文案中保留原始值以便定位。界面 MUST NOT 将原始英文枚举作为唯一可见状态内容。

#### Scenario: 读取未映射的历史状态

- **WHEN** 用户可见数据包含未被当前版本识别的状态值
- **THEN** 系统显示包含“未知状态”的中文兜底文案及原始值，而不影响页面继续加载

### Requirement: 内部状态兼容性

系统 MUST 继续使用既有英文状态枚举进行数据持久化、接口传输和状态流转判断。状态中文化不得修改已有记录、不要求数据库迁移，也不得改变可选状态集合或业务流转规则。

#### Scenario: 更新已知排班状态

- **WHEN** 管理员在中文状态下拉选择“已完成”并提交
- **THEN** 系统向内部状态更新接口传递与“已完成”对应的既有英文枚举，并沿用既有完成登记校验
