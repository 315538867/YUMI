# 移除固定成本分摊设计

- 方案来源：`docs/solutions/2026-09-06-remove-fixed-overhead-costing-solution.md` v1.0
- Change ID：`remove-configurable-target-effective-minutes`
- 状态：已完成

## Context

当前成本设置将月度固定成本除以目标有效工时，生成固定成本时薪，并在商品预览、订单快照和产能报表中参与预计成本。详见 `proposal.md` 的动机。

## Goals / Non-Goals

**Goals:**

- 从用户可见设置和成本计算口径中彻底移除固定成本分摊。
- 保持已有 SQLite 数据和历史订单可读。
- 将新成本口径限定为材料、包装、默认兼职时薪和按件提成。

**Non-Goals:**

- 不重建或删除 `cost_settings_history` 的历史列。
- 不回算旧订单成本。
- 不调整排班、实际生产成本和人员结算。

## Decisions

1. **从领域输入/输出与共享契约删除固定成本字段。** 这样客户端和服务端均不能再传入或展示固定成本分摊；相比仅隐藏页面字段，能避免报表和订单继续隐式计入该成本。
2. **SQLite 历史列保留并写入占位值。** 删除列需要重建表，风险高且无业务收益；新记录以 `0 / 9600 / 0` 填充旧列，读取时忽略。相比迁移重建，能兼容所有既有本地数据。
3. **旧订单不回算，新建或更新订单使用新口径。** 这保持历史订单金额可追溯，避免删除设置后静默改变历史利润。

## Risks / Trade-offs

- [旧订单预计成本仍可能含历史固定成本] → 保留历史快照和数值，不再向新订单扩散，并在方案中明确该边界。
- [数据库存在未使用历史列] → 保留为兼容层，避免破坏性迁移；后续若需要数据库瘦身，可另立迁移。
- [成本报表口径变化] → 通过领域、服务、订单和报表回归测试锁定新成本构成。

## Migration Plan

1. 发布新应用后直接读取既有数据库；无需数据迁移。
2. 新保存的成本设置写入兼容占位值，但业务层不再暴露或计算固定成本。
3. 回滚时可恢复旧程序读取已有历史列；新写入的占位值仍为有效数据。
