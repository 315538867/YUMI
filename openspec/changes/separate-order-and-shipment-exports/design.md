# 设计：订单表与发货清单成品化版式

## 上下文

本变更的第 1 阶段已完成导出动作分离。本第 2 阶段只替换两个服务导出方法生成 XLSX 的内部实现，不调整对外方法签名。

## 决策

### 1. 采用 ExcelJS

`xlsx` 社区版适合数据工作表，但不提供可靠的图片嵌入与成品版式控制。新增 `exceljs` 生产依赖，以 workbook/worksheet API 设置列宽、合并区域、边框、填充、数字格式、打印属性并添加图片。现有 SheetJS 继续保留给其他业务报表。

### 2. 以专职构建模块封装版式

新增 `src/main/services/export-document-workbook.ts`，暴露 `createOrderSheetWorkbook` 和 `createShipmentManifestWorkbook`。`StudioService` 负责查询、业务校验、金额/累计数量组装与无副作用保证；构建模块只根据传入视图模型创建 workbook。这样不会把版式和仓储查询继续堆在 `studio-service.ts`。

图片通过 `imagePathByProductId` 映射按单个项目读取。文件不存在、不是 png/jpeg/gif 或读取失败时跳过该图，不抛出整单错误。

### 3. 数据口径

订单表：订单创建日期使用 `YYYY.MM.DD`；单行价格取订单已确认单价与订单商品快照中的单件包装费、替换袋费用，按 `总单价 = 理望单价 + 包装费 + 替换袋`、`总金额 = 总单价 × 订购数量` 计算。

发货清单：以所选 shipment 校验归属。对每一个订单商品生成一行；本次发货数量由 shipment item 映射提供，未命中为 0；累计已发/未发数量使用 `getOrderShipmentSummary(order.id)` 的当前快照。页首总发货数仅求所选 shipment 的数量和。

### 4. 版式

两个工作表均使用横向打印、单页宽度、默认中文字体、细边框、居中对齐、产品图列和自适应商品行高。订单表使用黄色表头；发货清单使用用户样例中的简洁黑边框表头。两者均使用可读取的标准 XLSX 数字单元格，不把数量或金额写成字符串。

## 取舍

产品图片不加入订单商品快照，因此历史订单使用导出时当前商品图片；保留订单价格快照可避免价格漂移。发货清单历史记录的未发货数量是当前累计状态，这与用户确认的“按截图”全订单展示方式相匹配。

## 验证策略

服务测试使用临时 PNG 文件和 ExcelJS 回读生成的 buffer，断言工作表名、合并标题、字段单元格、计算结果、全订单发货行、合计/页尾与图片嵌入；保留导出不改写数据库及发货记录归属拒绝断言。先以这些断言使现有实现失败，再加入依赖和实现使其通过。
