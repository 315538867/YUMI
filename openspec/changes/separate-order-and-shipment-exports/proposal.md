# 提案：订单表与发货清单分离导出

- Change ID：`separate-order-and-shipment-exports`
- 方案来源：`docs/solutions/2026-09-06-separate-order-and-shipment-exports-solution.md` v3.0
- 状态：第 3 阶段“发货历史快照与排班任务唯一性”已确认，待实施；第 2 阶段人工保存验收仍待完成
- 最后更新：2026-09-07

## 为什么

第 1 阶段已分离订单表和单次发货清单的保存入口，但导出内容仍是基础字段表格，无法满足客户确认和发货签收所需的正式单据样式。用户提供了订单表与发货清单样例，并确认两个单据都应嵌入产品图片、采用完整表格样式；同时明确发货清单应展示订单全部商品、采购总数量、本次发货数量和未发货数量。

## 变更内容

- 引入 ExcelJS 构建具备样式、合并单元格、打印设置和图片嵌入能力的订单表、发货清单。
- 订单表改为客户信息、`订单表` 标题、报价构成、图片明细和合计行。
- 发货清单改为客户/发货总数、全订单商品、采购总数量/本次发货数量/未发货数量、合计及发货页尾信息。
- 保持既有独立保存入口和不写入业务数据的边界不变；默认文件名统一调整为保存时刻、表格类型和客户名称。

## 影响

- 受影响实现：`package.json`、`package-lock.json`、`src/main/services/studio-service.ts`、新增工作簿构建模块、服务层测试。
- 不影响：共享 API 契约、预加载桥接、订单详情按钮、订单/发货记录数据模型和已有发货保存流程；IPC 仅调整默认文件名构成。
- 风险：产品图片文件不可用时单元格留空；ExcelJS 替换仅限这两份单据，不迁移其他 SheetJS 报表。


## 第 3 阶段补充范围

1. 发货记录保存或编辑时，固化该条发货清单的完整历史快照；后续新增发货不得改变旧清单的未发货数量。
2. 导出优先读取持久化快照；旧记录按创建时的历史发货顺序推算，禁止按下载时的最新累计发货量计算。
3. 排班选择任务时，同一张排班内同一订单下同一产品只能出现一次；前端隐藏已选择项，服务端拒绝绕过界面的重复保存。
