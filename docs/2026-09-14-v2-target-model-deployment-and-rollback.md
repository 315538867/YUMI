# V2 商品、工序、工资与公式中心目标模型：部署与回滚说明

- 日期：2026-09-14
- 变更：`redesign-product-process-payroll-and-costing`（商品、工序、工资与公式中心重构）
- 适用版本：包含本变更的桌面应用（Electron 单机离线）
- 关联方案：`docs/solutions/2026-09-14-product-process-payroll-and-formula-center-solution.md`

## 1. 结论先行

本次发布**直接建立目标数据库模型，不迁移、不兼容任何旧业务数据**。

| 事项                                   | 是否执行                           |
| -------------------------------------- | ---------------------------------- |
| 备份旧数据库与附件（保留原始文件）     | 必须                               |
| 把旧数据导入新库                       | **禁止**；不提供任何导入脚本或工具 |
| 删除或重建目标业务数据库               | 必须                               |
| 在新模型中重新录入商品、人员与现场存量 | 必须                               |

备份唯一目的是"出问题时能回到旧应用 + 旧库"，**不是**数据迁移的前置步骤。

## 2. 新旧模型差异摘要

- 商品：只保留单件材料重量与固定成本、缝边耗材成本、三道计件提成、四道工序预计单件时长与产能；删除胶水用量、材料损耗率、旧人工成本与内部缝边成本字段。
- 工序：制作 → 捏毛装袋 → 条件缝边 → 打包发货；`shipping` 不再是兼职岗位。
- 工资：制作按合格数量计件并按不合格数量扣冻结材料成本（无时薪）；捏毛装袋与缝边按负责人确认的整段时长与个人时薪加完成数量提成；打包发货只按确认时长。
- 存量：历史数量改为商品维度的阶段存量（商品详情「商品存量」），不再要求绑定订单。
- 公式：商品预计盈利、订单金额、工资与结算金额共用同一份结构化公式定义。

旧库中的商品、订单快照、排班、履约事件、期初在制品、工时、工资与结算记录**不会**出现在新库中，也不应试图恢复。

## 3. 部署步骤

### 3.1 准备（发布前）

1. 关闭应用的所有实例（含子窗口），确认进程已退出。
2. 定位应用数据目录（Electron `userData`），确认其中的 V2 业务文件：
   - 数据库：`yumi-studio-v2.sqlite`（连同同目录的 `-wal`、`-shm` 文件）
   - 附件：`attachments-v2/`
   - 备份：`backups-v2/`
3. 复制上述数据库与附件目录到安全位置（外部磁盘或另一台电脑），并**打开副本确认可读取**（例如用 SQLite 工具执行一次 `SELECT COUNT(*) FROM products;`）。
4. 记录备份文件路径与时间，交由负责人确认"备份存在且可读"。

### 3.2 重建目标数据库

1. 删除应用数据目录下的 `yumi-studio-v2.sqlite`、`yumi-studio-v2.sqlite-wal`、`yumi-studio-v2.sqlite-shm`。
2. 启动新版本应用：首次启动会按最新结构建立空库、默认设置与必要索引。
3. 若旧库被误留，应用会拒绝启动并提示：
   「数据库结构与当前版本不兼容：缺少 products.edge_consumable_cost_cents。请先备份旧业务库，再按最新结构重建数据库。」
   此时按 3.2.1 与 3.2.2 处理，**不要**尝试用工具补列或手工改库。
4. 不要恢复 `attachments-v2/` 中的旧附件到新库：新库不引用旧记录，可以整体清空或保留原目录结构（新上传的附件会写入同一目录）。

### 3.3 在新模型中重新录入（负责人操作）

1. **设置**：工作室参数页维护全局材料克单价、订单默认预留天数，以及捏毛装袋、缝边、打包发货三道工序的预计基准时薪。
2. **人员**：重新建立兼职人员并录入生效日期与个人时薪（实际工资只使用工作日期生效的个人时薪）。
3. **商品**：在商品页「新建商品」全页工作区录入单件材料重量、包装/配饰/替换袋/缝边耗材/单件固定成本、三道计件提成、四道工序预计单件时长与产能参数；右侧预计盈利预览会立即显示预计单件成本、利润与利润率。
4. **现场存量**：进入每个商品的「商品存量」标签，按实际物理阶段录入历史数量：已制作待捏毛装袋、已捏毛装袋未缝边、已缝边待打包发货、已打包待发货。录入只登记阶段、数量、发生日期与备注，不会生成历史任务或历史工资。
5. **投入订单**：对仍在履约中的订单，使用「投入订单」把对应商品的阶段存量投入同一商品的订单商品；需要缝边的订单按剩余缝边需求进入待缝边，其余进入待打包发货，已缝边的存量只能投入仍有缝边需求的订单。

### 3.4 发布后验证清单

- 新建商品保存成功，商品详情「成本与预计盈利」显示预计成本、利润、利润率与缝边预计增加成本，且公式与代入值直接可见。
- 新建订单保存后，编辑商品不影响该订单的冻结快照（提成、材料克单价、预计时长）。
- 排班 → 制作结果与质量确认 → 次日「待核算」录入整段时长与多商品完成明细 → 结算草稿的计时工资、计件提成与材料扣款与录入一致。
- 工资结算确认后生成一笔工资支出流水；月度经营报表可见该笔支出。
- 「数据保护」页备份可用，且恢复后应用能正常启动。

## 4. 回滚步骤

当新模型发布验证失败、需要回到旧版本时：

1. 关闭新版本应用。
2. 卸载/替换回旧版本应用（保持原安装路径）。
3. 删除新模型产生的 `yumi-studio-v2.sqlite`（连同 `-wal`、`-shm`）。
4. 把 3.1 备份的旧 `yumi-studio-v2.sqlite`（及旧 `attachments-v2/`）放回原路径。
5. 启动旧版本应用，检查商品、订单、排班、工资与财务数据是否与备份时一致。

**新旧模型不得共用同一个业务库**：旧库缺少目标列会触发兼容守卫直接拒绝启动；新库包含新结构，旧应用同样无法正确读取。回滚必须成对替换"应用版本 + 数据库文件"。

## 5. 常见问题

**Q：能不能只把旧商品数据导进新库？**
A：不能。本变更明确不提供导入路径；旧口径（胶水用量、损耗率、制作时薪、期初在制品）与新模型没有一一对应关系。请按 3.3 重新录入。

**Q：备份文件还有用吗？**
A：有，用于回滚（第 4 节）。它保留的是旧应用的完整数据，不会被新应用读取。

**Q：误删旧库后还能启动新版本吗？**
A：可以，新版本会直接建立空库。但旧数据将无法找回，因此 3.1 的备份必须先于 3.2 完成。

**Q：应用启动报「数据库结构与当前版本不兼容」怎么办？**
A：说明数据目录里仍是旧库。先按 3.1 备份，再按 3.2 删除旧库文件后重启；不要手工补列。
