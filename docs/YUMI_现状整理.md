## 一、功能模块（按主导航分组）

### 工作

- **工作台**：聚合「需要我决定」（待质检、待确认工资、待退款、售后处理）与「可以推进」（待派工序、待发货、待报销）两个互斥视图；事项由既有事实只读生成，点击深链到真实处理区；空库时给出「先建客户→建商品→建订单」唯一首用引导。

### 业务运营

- **订单**：多商品明细（数量/成交单价/缝边/明细优惠）、订单优惠、金额调整与内容变更记录、预计发货日期+预留天数→制作截止日、收货地址快照、备注、成本详情弹窗。详情分六个 Tab：概览/排班/发货/资金/盈利/售后。
- **排班（生产任务）**：固定四工序「制作/捏毛装袋/打包/发货」；订单视角与人员周历双视角、行内派工、超排/超派风险、缺勤/取消、期初在制品补录。
- **工资（结算）**：期间选择、排班与考勤双口径参考、最终实发、确认即生成工资支出、待退款处理、人员与时薪维护。

### 资金与分析

- **财务**：月度经营结果（按实际收付款日期）、现金流水（统一来源）、待报销（私人垫付+批量报销）、收支类目/垫付人维护。
- **报表**：月度经营、商品产能风险、交期风险、订单核算、排班进度、已确认工资；筛选与导出口径一致。

### 基础资料

- **客户**：姓名/昵称、联系方式、默认收货地址、启用状态、备注；详情含订单统计（订单数/金额/净收款/待收）与历史订单行。
- **商品**：资料+默认售价+制作参数（标准制作时长、单件提成、胶水扣款、材料克重/损耗、配件费/替换袋、捏毛装袋、内部缝边成本）+模具产能（模具数×单模具产量×每日批次）。改参数只影响新订单，历史订单走快照。
- **设置**：工作室参数（胶水单价、默认预留天数）、计算公式说明、财务资料、数据保护（备份/恢复/导出）、V2 独立数据空间。

### 随订单详情承载的附属能力

- **发货**：分批发货批次（多商品数量、快递/单号/备注）；累计已发/待发自动计算；批次只读、作废留痕；清单绑定单批次导出。
- **售后**：处理单（日期、原因、客户要求、责任归属、处理内容、状态、收费说明、核算成本）；返工/补发由负责人显式发起。

## 二、核心工作流

### 1. 订单经营主链

列表 → 新建 → 详情六 Tab。

- 资金状态 = 当前订单金额（订单应收+金额调整）− 净收款 → 未收款/部分收款/已结清/退款中/已退款/超收
- 资金记录三类：`payment 收款 | refund 退款 | after_sales_charge 售后收费`；收款/售后收费计 income、退款计 expense；改错只能「冲正并更正」（原记录+冲正+替代三段关联，被冲正双方都不计入）
- 减额与退款独立：负金额调整只改待收，不自动生成退款

### 2. 生产排班链（四工序）

- 需求 = 订购数量；有效已排只计 `pending 待完成`/`pending_inspection 待质检`，`confirmed/cancelled` 不占额度；预计覆盖>需求必须确认风险才能保存；缺勤/请假/取消立即释放为未排/待补排，超派显示异常不静默裁剪
- 任务状态机：`pending → 报数 → pending_inspection → 质检（合格+不合格=提交数量）→ confirmed`；合格进入下一工序，不合格不进入并产生质量扣款事实；返工/补发=新的正常任务
- 阶段流：待制作→待捏毛装袋→待打包→待发货→已发货，各阶段数量由履约事件汇总；发货累计不得超过待发货可用量

### 3. 发货链

批次 `active → voided`（作废需日期+原因，重算累计，不可改删）；导出不改状态、不产生记录。

### 4. 售后链

`open → processing → resolved / cancelled`；系统不自动判定责任、不自动收费、不自动建返工/补发；售后核算成本只进订单成本、不进经营支出。

### 5. 工资链

`draft 草稿`（选期间，默认上一完整自然周）→ 汇总两套参考（排班分钟/考勤分钟，提成与扣款同源、不相加）→ 负责人填实发+付款日期+备注 → `confirmed 已确认`（同事务锁定分配并只生成一笔工资支出）。扣款 `pending → partially_deducted → settled` 余额顺延；已确认后发现不合格转待退款 `pending → refunded`。

### 6. 资金/对账链

订单资金 + 工资支出 + 日常收支 + 报销 → 统一财务流水 → 按实际付款日期归月统计（创建/排班日期不作口径）；私人垫付录入即计经营支出并进待报销，报销只作现金流、不重复计支出。

## 三、用到的公式

### 全局精度约定

证据：`src/shared/money/index.ts`

- 金额一律**整数分**（Cents），禁止浮点除法参与业务金额；唯一的三个除法点用 decimal.js 且仅在最后一步 `ROUND_HALF_UP`
- 录入解析：元→分最多 2 位小数；胶水单价→微元/克最多 6 位；克重→毫克最多 3 位
- 材料用量按 HALF_UP 取整到毫克

### 1. 订单金额与订单资金

| 公式         | 表达式                                                           | 证据                                  |
| ------------ | ---------------------------------------------------------------- | ------------------------------------- |
| 商品金额     | 数量 × 成交单价                                                  | `src/main/domain/order-amounts.ts:72` |
| 缝边金额     | 缝边数量 × 缝边单价；缝边数量默认=商品数量且不得超过             | `order-amounts.ts:61-66,74`           |
| 商品行应收   | 商品金额 + 缝边金额 − 明细优惠                                   | `order-amounts.ts:85`                 |
| 订单应收     | Σ行应收 − 订单优惠                                               | `order-amounts.ts:107`                |
| 当前订单金额 | 订单应收 + Σ金额调整（可正可负）                                 | `order-amounts.ts:115`                |
| 净收款       | Σ未冲正 income − Σ未冲正 expense（被冲正原流水与冲正流水都不计） | `order-funds.ts:60-83`                |
| 待收款       | 当前订单金额 − 净收款（可为负）                                  | `order-funds.ts:81`                   |
| 制作截止日   | 预计发货日 − 预留天数（默认 2；无发货日则 null）                 | `order-schedule.ts:44-53`             |

### 2. 商品成本（订单快照口径）

`calculateProductSnapshotCostCents`（`src/main/domain/product-costing.ts:19-67`）：

```
其他成本 = (包装 + 配饰 + 替换袋) × 数量 + 内部缝边成本 × 缝边数量

材料/胶水（三选一，按优先级）：
 a) 材料公式：胶水单价 × [数量 × 单件毫克 × (10000+损耗万分比)/10000] ÷ 1e7
 b) 胶水公式：胶水单价 × 单件胶水毫克 × 数量 ÷ 1e7
 c) 旧快照：materialCostCents × 数量

总成本 = 材料/胶水 + 其他成本
```

- 单价单位微元/克、重量毫克，1 分 = 1e7 乘积单位（`src/shared/money/index.ts:77-103`）
- a/b 均按整批一次取整到分，避免逐件累计误差（`product-costing.ts:13-15`）
- 明确不含运费、制作/捏毛提成、不能归属的工资（`product-costing.ts:16-17`）
- 输入为下单时冻结的商品快照
- 每日模具产能 = 模具数 × 每模每批产出 × 每日批次数；三项不全为正时存 0（`product-capacity.ts:56-67`）

### 3. 多工序生产与提成

- 任务计划分钟：制作 = 计划数量 × 标准制作分钟 + 额外分钟；其他工序 = 负责人计划分钟（额外分钟仅制作可用）（`fulfillment.ts:103-128`）
- 合格提成 = Σ（仅 `making`/`fluffing_bagging`：合格数量 × 该任务冻结单件提成）；打包、发货恒为 0（`settlement.ts:129-137`）
- 费率来源链：商品快照 `makingCommissionCents` / `fluffingBaggingCommissionCents`（缺省 0）→ 任务冻结 `piece_rate_cents` 与 `rate_snapshot`
- 制作不合格扣款 = 不合格 × 制作提成 + 不合格 × 标准制作分钟 ÷ 60 × 时薪 + 胶水扣款（有胶水公式则按本批精确算，否则单件 `glueCostCents` × 数量）（`settlement.ts:140-168`）
- 捏毛装袋不合格扣款 = 不合格 × 捏毛提成 + (计划分钟 × 不合格 ÷ 计划数量) ÷ 60 × 时薪；不扣胶水（`settlement.ts:171-198`）

### 4. 工人工资与结算

- 时薪工资 = 分钟 ÷ 60 × 时薪（HALF_UP 到分）（`src/shared/money/index.ts:132-142`）
- 结算排班分钟 = Σ任务(planned_minutes + extra_minutes)；结算统一时薪取「结算结束日生效的个人时薪历史」
- 扣前应发 = max(0, 时薪工资 + 合格提成 + 其他调整)
- 可扣上限 = min(可扣款, 排班口径扣前应发)
- 参考工资 = max(0, 扣前应发 − 可扣上限)，排班/考勤两套仅时薪分钟来源不同、独立归零
- 抵扣分配：按扣款记录时间序逐个 `min(剩余待抵扣, 可用上限)`，余额顺延
- 实发由负责人填写（≥0，确认时须>0），确认即生成一笔 `worker_settlement/wage_payment` 支出

### 5. 资金/报销/现金流

- 月经营收入 = 当月全部 income 流水（按实际收款日归月）
- 月经营支出 = 当月 expense 且 sourceType ≠ `reimbursement`（报销是付款，不重复计支出）
- 月经营结果 = 收入 − 支出
- 待报销 = 截至查询日已发生、且无当日或更早完整报销的私人垫付之和；报销必须等额、一对一（`finance.ts:150-213`）
- 售后 `accountingCostCents` 只作订单成本参考，不生成现金支出或客户收费

### 6. 报表指标

- 商品行收入 = 行应收（含缝边、减明细优惠）；商品成本 = 快照成本（按批量）
- 行毛利 = 行收入 − 商品成本；毛利率万分比 = round(毛利 × 10000 ÷ 行收入)，收入 0 时为 null（`report-service.ts:166-187`）
- 订单已知核算成本 = Σ商品成本 + 该订单全部售后 `accounting_cost_cents`
- 订单已知利润 = 净收款 − 已知核算成本（现金口径，不含工资/提成/运费）
- 总计行 = 各订单行同名字段直接相加
- 月度经营 = 财务月度汇总 + 当月 `paid_on` 开头的已确认结算实发合计
- 履约阶段：以订单行数量为「制作」初值，按事件加减流转（`fulfillment.ts:145-213`）
- 产能风险：可用产能 = 日产能 × 含头尾日历天数；缺口 = max(需求 − 可用, 0)；利用率万分比 = ceil(max(需求, 已排) × 10000 ÷ 可用)（`report-service.ts:337,378-384`）
- 交期风险：截止日差 <0 为 critical，≤ 预警天数（默认 2）为 warning（`report-service.ts:449-456`）
- 发货清单：待发 = max(订单数量 − 累计已发, 0)；指定批次优先读冻结快照，作废批次本批数量仍读冻结值但累计按当前有效批次

### 7. 口径差异与实现边界（重要）

1. **快照 vs 实时**：商品成本与胶水单价按下单快照冻结，后续改商品参数不回写（`v2-order-service.ts:101-131,751-754`）
2. **结算时薪双口径**：参考工资统一用「结算结束日生效个人时薪」，而任务表冻结的 `hourlyWageCents` 仅用于不合格扣款与历史兜底——同一任务参考工资与扣款可能用不同时薪
3. **工作台预览与结算单不一致**：工作台待确认工资兜底展示 = 参考工资 + 合格提成 − 实际扣款 + 其他调整（`workbench-service.ts:205-211`），而参考工资已含提成与扣款，疑似重复计算，仅展示用
4. **「预计人工/预计提成」已不在商品成本内**：`openspec/specs/order-cost-details`、`product-catalog-and-costing` 仍描述「预计成本含人工与提成」，与现实现分叉；人工/提成只经工序任务→结算单承载
5. **全局默认兼职时薪已移除**：V2 工作室参数仅胶水单价 + 预留天数（`studio-settings-service.ts:8-9,53-68`），与 2026-09-06 方案记载不同
6. `studio-reporting` spec 的「本月捏捏总重量」在 `src` 中无实现
7. 未接入服务层的遗留计算（仅测试引用）：`production.ts:20-104`（实际生产人工/计件/覆盖数量）、`scheduling.ts:45-91`（排班预警预览）、`shipment-quantities.ts:33-55`

## 四、操作步骤（模块 → 路径）

- **建单**：订单 → 新建订单 → 选/建客户（可一键复制客户收货地址）→ 加多商品行（数量、成交单价、勾缝边自动带数量、明细优惠）→ 填预计发货日期、订单优惠、备注 → 保存 → 进入只读概览
- **收款/退款**：订单详情 → 资金 → 登记收款/登记退款（金额>0、发生日期、支付方式、可选凭证）→ 流水按日期倒序；纠错在原流水行「冲正并更正」
- **派工**：排班 → 订单视角 → 选阶段标签（制作/捏毛装袋/打包/待发货）→ 工序行「+ 派工」（人员、日期、数量；制作填额外预留分钟，其他工序必填计划分钟）→ 超排需确认；或 人员周历 → 空白格「+ 派工」
- **报数/质检**：排班 → 工作安排与质检 → 待完成任务 → 提交完成数量 → 次日质检填合格/不合格 → 确认质检
- **发货**：订单详情 → 发货 → 新增发货（各商品数量≤可发、日期、快递/单号/备注）→ 保存；历史批次 → 导出本批清单 / 作废本批（填作废日期与原因）
- **售后**：订单详情 → 售后 → 新增售后单（原因、责任、处理内容、收费说明、核算成本）→ 保存后按需显式创建返工任务或补发批次
- **期初在制品**：排班 → 补录期初在制品 → 搜索订单商品（结果行显示订单号/客户/商品/确认数量）→ 选阶段（待捏毛装袋/待打包/待发货）+数量+日期 → 保存
- **工资**：工资 → 新建结算（选人员+日期范围）→ 核对排班/考勤两套参考 → 填最终实发、付款日期、备注 → 确认；待退款页处理退款（填实际退款金额≤待退款）
- **财务**：财务 → 月度经营结果（收入/支出/结果/待报销）→ 现金流水（按日期与来源筛选）→ 待报销 → 勾选多笔 → 批量报销（统一日期/方式/备注，原子提交）；登记收支时支出须选启用类目，私人支付须选垫付人
- **报表/导出**：报表 → 切各区块（月度经营、商品产能风险、交期风险、订单核算、排班进度、已确认工资）→ 按级别筛选 → 导出当前报表/订单表/发货汇总；订单表入口在订单详情概览，发货清单只在批次上
- **设置与数据**：设置 → 工作室参数「编辑工作室参数」；「立即备份」生成带时间的备份包；数据保护 → 选包恢复（先备份当前数据+二次确认，仅 V2）；财务资料维护收入/支出类目与垫付人（停用可不删）
- **商品**：商品 → 新建商品 → 单页填资料、成本参数、模具产能 → 保存；改参数只影响新订单，历史订单快照不变
