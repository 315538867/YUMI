# 全局默认兼职时薪与商品成本预估方案

- 方案版本：v1.1
- 设计时间：2026-09-06
- 最后修改时间：2026-09-06
- 修改人：Codex
- 关联 OpenSpec：`global-default-worker-hourly-wage`
- 提案名称：全局默认兼职时薪
- 当前实施状态：已完成

## 1. 背景与当前行为

当前商品成本预估由调用端在每次预览时传入临时“预估时薪”。新建商品预览默认传入 0，商品详情预览允许人工填写临时时薪；该值既不受系统设置统一管理，也不会作为订单预计人工成本的快照。兼职人员则单独维护个人时薪，并已用于实际制作成本结算。

这会导致商品录入、报价预估和订单预计成本没有统一人工成本口径。

## 2. 目标行为

系统提供一个版本化的“默认兼职时薪”全局成本设置。商品新建和商品详情的成本预估自动使用该值，页面明确展示当前采用的全局时薪且不再允许在预览区域临时修改。创建或编辑订单时，订单商品快照保存当时的默认兼职时薪，并用其计算预计人工成本；以后改动全局设置不会回算既有订单的预计成本。

兼职人员的个人时薪及其历史版本保持不变。班次实际制作成本仍按实际人员在当日有效的个人时薪计算，不会被全局默认时薪覆盖。

## 3. 详细设计

### 3.1 全局成本设置与历史

在 `cost_settings_history` 新增 `default_hourly_wage_cents`，用迁移为已有数据库填充 0。共享 `CostSettings` 与更新输入新增 `defaultHourlyWageCents`；每次保存成本设置将该值和其他成本参数一起新增一条历史记录，并纳入审计。

默认值允许为 0，以兼容尚未配置时薪的既有数据；所有金额必须为非负整数（分）。

### 3.2 商品成本预估

`products.previewCost` 不再接收调用端提供的时薪。服务层读取当前成本设置的 `defaultHourlyWageCents`，并将其传给成本领域计算；预览返回 `appliedHourlyWageCents`，让界面展示实际采用的全局口径。

新建商品和商品详情的成本预估移除临时“预估时薪”输入，改为只读提示“按全局默认兼职时薪 X 元/小时计算”。

### 3.3 订单成本历史快照

`ProductOrderSnapshot` 新增 `defaultHourlyWageCents`。订单新建、修改并重新计算商品明细时，使用当时当前成本设置创建快照并计算预计成本。已有订单的 JSON 快照缺失此字段时按 0 兼容读取，因此不会破坏历史数据。

### 3.4 设置界面

“设置与备份”页面新增“系统成本设置”区域，支持读取和保存：胶水单价、默认兼职时薪和生效日期。保存成功后刷新全局数据；商品预览每次调用服务端，因此会自动采用新值。

### 3.5 实际成本边界

全局默认兼职时薪仅服务于商品与订单的**预计人工成本**。实际制作记录继续使用排班人员的个人时薪历史计算 `actualLaborCostCents`，不改变现有结算逻辑。

## 4. 验收标准

1. 成本设置可以维护并读取默认兼职时薪，历史记录与审计内容包含该值。
2. 商品新建和详情成本预览不再接受临时时薪，返回并展示全局默认时薪；人工成本金额正确。
3. 新建订单的预计成本包含创建当时的默认时薪；后续修改设置不改变历史订单的预计成本与快照。
4. 兼职人员实际制作成本仍按人员个人时薪计算。
5. 旧数据库迁移后能够读取现有成本设置与订单快照。
6. 类型检查、lint、全量测试、构建及 OpenSpec 严格校验通过。

## 5. 风险与非目标

- 旧成本设置或订单快照没有新字段时按 0 兼容，因此旧订单不会被追溯改价。
- 本期不把员工个人时薪改为可空字段，不做“个人未设置时薪时自动回退全局”的薪资结算逻辑。
- 本期不回填或重算既有订单的预计人工成本。
