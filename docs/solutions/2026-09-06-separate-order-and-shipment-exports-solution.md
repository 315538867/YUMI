# 订单表与发货清单分离导出方案

- 方案版本：v3.0
- 设计时间：2026-09-06
- 最后修改时间：2026-09-07
- 修改人：Codex
- 关联 OpenSpec：`separate-order-and-shipment-exports`
- 提案名称：订单表与发货清单分离导出
- 当前实施状态：第 1 阶段已实施；第 2 阶段自动化验证已完成；第 3 阶段“发货历史快照与排班任务去重”已确认，待实施

## 1. 背景与当前行为

第 1 阶段已将订单表和发货清单拆为两个独立 XLSX 文件：订单层级可生成订单表，每条已保存的发货记录可保存发货清单。用户现补充两张业务单据样例，要求两个文件均从“字段明细导出”升级为可直接发送、打印和签收的成品 Excel 单据，并在产品列中嵌入产品图片。

## 2. 已确认的业务规则

1. 订单表和发货清单仍分别保存为独立 XLSX 文件，入口、IPC、默认文件名和取消保存行为不变。
2. 两份单据都使用 ExcelJS 生成，均只包含一个工作表，并嵌入已保存的产品图片；产品无图片、图片路径失效或格式不支持时，图片单元格留空且导出继续完成。
3. **订单表**面向客户确认；标题固定为 `订单表`；订单创建日期以 `下单日期：YYYY.MM.DD` 显示在顶部客户资料区。
4. 订单表明细列固定为：`序号｜产品图｜产品名称｜产品克重｜产品单价｜包装费｜替换袋｜总单价｜订购数量｜总金额｜备注`。
5. 订单表的 `总单价` 按 `产品单价 + 包装费 + 替换袋` 计算；`总金额` 按 `总单价 × 订购数量` 计算，并在底部汇总订购数量和总金额。产品单价取订单明细的已确认单价；包装费和替换袋取订单商品快照的单件包装费与替换袋费用。
6. **发货清单**仍以单条已保存发货记录为依据，但按用户示例展示订单的全部商品，而不仅是本次实际发货商品。
7. 发货清单明细列固定为：`序号｜产品图｜产品名称｜采购总数量｜本次发货数量｜未发货数量｜备注`。采购总数量取订单数量；本次发货数量仅取所选发货记录内的该商品数量，不在本次记录中的商品显示 `0`；未发货数量必须为保存该条发货记录当时的待发数量，最小为 `0`。
8. 发货清单标题为 `M. D发货清单`（取该记录发货日期）；顶部显示客户与本次发货总数；底部显示采购总数量、本次发货总数、未发货总数、发货时间、收货人和该次发货备注。
9. 保存发货记录时，系统必须将该次单据的客户、日期、备注、全订单商品、采购总数量、本次发货数量、未发货数量及当时图片路径固化为发货清单快照。后续导出历史发货清单只读取该快照，不得因后续发货、订单修改或商品资料修改而改变历史数据；编辑该条发货记录后，才重新生成该条快照。对于升级前未存快照的记录，系统按该记录的创建先后从历史发货记录推算一次，并在之后保持不受后续记录影响。
10. 订单文件与发货清单文件的默认保存名统一为 `yyyyMMdd-HHmmss-表格类型-客户名字.xlsx`；保存时刻取用户点击保存操作的本机时间，例如 `20260906-231500-订单表-陈.xlsx`。

## 3. 文件版式设计

### 3.1 订单表

- 工作表名为“订单表”，横向打印、单页宽度适配；顶部合并单元格分别展示客户名、联系电话、收货地址与订单标题。
- 黄色加粗表头、细边框、明细区垂直/水平居中；产品图列固定宽度，商品行按图片高度加高。
- 金额列显示人民币金额且保留两位小数；产品克重以 `0.00` 显示。
- 合计行合并前置文字区域，显示“合计”、订购数量和总金额。

### 3.2 发货清单

- 工作表名为“发货清单”，横向打印、单页宽度适配；第一行合并显示发货清单标题，第二行显示客户与本次发货总数。
- 表头、边框、图片列、行高和对齐方式与订单表一致，确保两份文件视觉统一。
- 每个订单商品均显示一行；本次未发货的商品显示本次发货数量 `0`，但仍保留其采购总数量、未发货数量与产品图片。
- 合计行汇总三类数量；页尾分别显示发货时间、收货人及发货备注。

## 4. 技术设计与边界

- 在 `package.json` 增加生产依赖 `exceljs`，服务层从 SheetJS 的 JSON 工作表改为 ExcelJS 工作簿；原有 SheetJS 仅继续服务于其他报表导出。
- 在 `src/main/services/studio-service.ts` 中保留 `exportOrderSheet` 与 `exportShipmentManifest` 的公开契约，内部改为调用一个专职的单据工作簿构建模块；IPC、预加载桥接和渲染层无需变更。
- 构建模块依据订单明细的 `productId` 查询当前产品图片路径。订单价格、克重、包装费和替换袋费用仍取订单快照，避免产品后来改价影响已确认订单。
- 图片读取失败必须被隔离到单个商品，不能使整份工作簿失败；仅支持 ExcelJS 可识别的 `png`、`jpeg`、`gif` 文件扩展名。
- 不重定义发货记录本身的可编辑数据或保存时机；发货清单总数/未发数量是导出快照，不回写数据库。

## 5. 验收标准

1. 订单表 XLSX 仅有“订单表”工作表，标题为 `订单表`，并具备客户信息、产品图片列、黄色表头、商品明细与合计行。
2. 订单表明细与合计中的总单价、订购数量、总金额符合 `产品单价 + 包装费 + 替换袋` 的已确认规则，金额为人民币两位小数。
3. 发货清单 XLSX 仅有“发货清单”工作表，标题、客户、发货总数、列结构、图片、合计和页尾字段均符合用户示例。
4. 对只发出部分商品的记录，发货清单仍展示订单全部商品；未发商品的本次发货数量为 `0`，未发货数量根据累计保存记录正确计算。
5. 历史发货清单再次导出不改动任何订单、商品或发货记录；无图或损坏图片不阻断导出。
6. 新增/调整的服务测试先失败后通过；类型检查、Lint、全量测试、生产构建、OpenSpec 严格校验及差异检查通过。

## 6. 风险与明确取舍

- 订单表展示口径完全遵从客户提供的版式，因此不在明细中展示缝边、明细优惠或订单级优惠；该单据的总金额按已确认的三项单价构成计算，而不等同于系统财务应收时，订单原有财务数据不作任何修改。
- 订单商品快照未保存图片路径，故图片采用导出时当前产品图片；产品图片后来被移除时，历史单据的图片格将留空，但文字和数量信息仍可导出。
- 发货清单的未发货数量是导出时的累计状态，而不是为每次历史发货记录持久化的历史余额；这符合“重新保存”时显示当前订单发货进度的要求。

## 5. v3.0：发货历史快照与排班任务唯一性

### 5.1 发货清单历史快照

- `shipments` 增加 `manifest_snapshot_json` 字段。保存或编辑发货记录时，在同一数据库事务内写入该条发货记录专属的完整清单快照。
- 清单导出优先读取该 JSON 快照；不再调用当前订单的累计待发汇总计算历史清单的“未发货数量”。
- 升级前没有快照的旧记录不以“现在的累计状态”导出，而是按该记录创建时刻之前的发货记录推算历史待发数量，兼容后续新增发货不影响旧记录。

### 5.2 同一排班内订单商品去重

- 唯一性范围是**同一张排班、同一订单、同一产品**；不同订单即使商品相同，仍可分别安排。
- 排班弹窗中，任务下拉框只显示尚未被其他任务选择的“订单 + 产品”组合；没有可选组合时禁用“添加任务”。
- 服务端在预览、创建和编辑排班时执行同样校验，防止异常调用绕过界面保存重复任务。
