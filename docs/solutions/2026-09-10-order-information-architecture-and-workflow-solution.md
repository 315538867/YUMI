## 1. 范围

本方案只重构订单模块的页面入口、详情信息层级、订单级/批次级操作边界，以及发货、资金两个工作视图的默认阅读与操作路径。

包含：

1. 订单模块的默认入口改为订单列表；
2. 订单详情默认进入只读概览，而不是编辑界面；
3. 订单概览的顶部摘要、商品主体、订单档案与订单级操作布局；
4. 发货页以发货批次列表为主，发货清单绑定单次发货记录；
5. 资金页以资金流水为主，收款、退款、冲正改为明确的上下文动作；
6. 编辑、作废、导出等操作的层级和留痕规则。

不包含：

- 修改订单、发货、资金流水的底层数据模型、审批权限或会计规则；
- 重新设计售后业务规则；
- 变更 Excel 单据的字段、样式或导出生成逻辑；
- 新增订单统计、报表或自动化提醒能力。

## 2. 当前行为

当前订单页面存在以下已确认问题：

- 进入订单后容易直接落到某张订单或编辑形态，缺少以列表开始的业务判断入口；
- 订单详情的“导出订单表、导出发货清单、合并导出、编辑订单内容”等按钮位于内容尾部，订单级动作没有固定的页面级位置；
- 顶部订单摘要以稀疏的三列/多卡片布局展示，只有少量数字但占用大量高度；
- “订单内容”只以一行商品摘要呈现，商品、数量、单价、小计与合计不能作为订单主体快速核对；
- 发货清单作为订单级按钮暴露，无法表达其属于某一次实际发货；
- 发货与资金视图默认混合浏览和编辑。尤其资金页同时并列收款/退款与冲正表单，首屏缺少可追溯的资金历史；
- 已生成的发货或资金记录缺少“先查看、再显式编辑/更正”的明确边界。

## 3. 目标信息架构

```text
订单模块
└── 订单列表（默认入口）
    ├── 搜索、筛选、订单状态与待办判断
    ├── 新建订单
    └── 点击订单
        └── 订单详情（默认：概览，只读）
            ├── 概览：商品主体、订单档案、最近发货摘要
            ├── 发货：发货批次列表与批次详情
            ├── 资金：订单资金流水与流水详情
            ├── 售后：沿用既有售后工作视图
            └── 显式编辑订单：仅通过详情页头部动作进入
```

核心原则：**列表负责判断，详情负责查看和处理，编辑只在用户明确发起后出现。**

术语规则：全局生产安排模块统一称为**排班**；订单详情内管理实际交付批次的工作视图统一称为**发货**，不再使用“履约”作为用户界面泛称。导航层级、页面头部和操作位置遵从关联的《YUMI 经营工作台设计规范 v2》。

## 4. 详细设计

### 4.1 订单列表：模块默认入口

订单模块打开时展示列表，不自动打开任一订单的编辑页。

列表提供：

- 搜索：订单号、客户、商品；
- 筛选：订单状态、发货进度、下单日期；
- 主列：订单号/客户、下单日期、订单金额、资金状态、发货进度、预计发货；
- 列表页右上角动作：`导出订单`、`新建订单`；
- 每一行同时支持点击行空白区域和点击明确的`查看详情`进入订单详情；
- 行尾`更多`只容纳低频辅助操作，不放置直接编辑按钮。

列表的编辑入口被移除，避免用户把列表误解为批量修改界面。

### 4.2 订单详情：默认概览与固定操作位

点击订单后进入订单详情的`概览`标签，默认所有订单主数据只读。

详情页头部结构：

- 左侧：订单号、客户、预计发货、制作截止、订单当前风险/状态；
- 右侧固定订单级动作：`导出订单`、`更多`、主按钮`编辑订单`；
- 订单级动作不再散落在商品内容、发货记录或页面底部。

`更多`只可容纳不属于商品、单笔资金或单次发货的低频订单动作。`导出发货清单`不得作为订单级动作存在。

### 4.3 概览页：紧凑摘要、商品主表与订单档案

#### 顶部摘要

将稀疏卡片改为同一行紧凑指标条，固定展示：

1. 订单金额；
2. 累计收款；
3. 待收款；
4. 发货进度（已发数量 / 订单数量）。

该摘要只表达高频经营判断，不承载完整订单字段。

#### 商品主表

“订单内容”升级为订单商品主表，默认展示：商品、数量、单价、小计，并在底部展示商品合计。多商品订单按行展开，不再压缩为一句商品文本。

商品相关修改通过`查看 / 编辑订单内容`或详情页主编辑动作进入，不在概览首屏直接出现表单。

#### 订单档案

订单档案固定为两组稳定只读信息：

| 分组 | 字段 |
| --- | --- |
| 客户与订单 | 客户、联系人/电话、下单日期、订单备注 |
| 交付与生产 | 预计发货、制作截止、收货信息、交付备注 |

订单档案展示关键字段，但不把概览变成完整编辑表单。编辑入口统一指向显式订单编辑页面。

#### 最近发货摘要

概览最多展示最近发货批次摘要或空状态，并提供`新建发货`/`查看全部发货`入口。摘要不可直接导出“订单发货清单”；具体清单必须进入对应批次。

### 4.4 发货页：发货批次是唯一清单归属

发货标签默认展示按时间倒序的发货批次列表，而不是新建发货表单。

每个批次展示：

- 批次编号与创建时间；
- 发货日期、物流公司、运单号；
- 本批实际发货的商品和数量；
- 签收/运输状态；
- 登记人；
- 行内操作：`查看详情`、`导出本批清单`。

发货页顶部保留订单级总览和`新建发货`，并可提供`导出发货汇总`。其中“发货汇总”与“本批发货清单”必须使用不同命名和不同语义，不能混用。

#### 发货批次生命周期

```text
新建发货
  → 选择本批商品、数量、收货与物流信息
  → 校验剩余可发数量，生成批次
  → 默认只读的批次详情
      ├── 导出本批清单
      ├── 显式编辑
      └── 作废留痕
```

- 发货批次生成后默认只读；
- 只有点击`编辑`才允许修改；
- 错误批次以`作废`保留历史痕迹，不允许直接删除；
- 本批清单必须随批次保存的实际商品、数量、物流和收货信息导出。

### 4.5 资金页：先看流水，再发起操作

资金标签默认展示订单资金流水和紧凑汇总，不能以并列录入表单作为首屏。

顶部紧凑汇总固定展示：订单金额、累计收款、累计退款、待收款。

资金流水按发生时间倒序，单条至少显示：发生日期、业务类型/说明、金额、支付方式、状态、登记人/凭证入口。

资金页右上角或明确的局部动作提供：`登记收款`、`登记退款`、`导出资金流水`。点击登记后打开独立抽屉或独立页面，成功提交后返回流水列表并新增对应记录。

#### 冲正规则

- 冲正不能作为脱离上下文的常驻表单；
- 用户必须从某一笔原流水的详情或行内动作发起`冲正`；
- 冲正记录关联原流水，原记录不被静默覆盖或删除；
- 详情中需可见原流水、冲正流水及其生效状态。

### 4.6 操作层级总表

| 操作 | 所属层级 | 固定位置 |
| --- | --- | --- |
| 新建订单 | 订单列表 | 列表右上角 |
| 导出订单 | 订单列表/订单详情 | 页面右上角 |
| 编辑订单 | 订单详情 | 详情页右上角主操作 |
| 新建发货 | 订单详情-发货 | 发货页右上角 |
| 导出发货汇总 | 订单详情-发货 | 发货页右上角次操作 |
| 导出本批发货清单 | 单次发货批次 | 批次行或批次详情 |
| 登记收款/退款 | 订单详情-资金 | 资金页明确操作 |
| 发起冲正 | 单笔资金流水 | 原流水行或详情 |
| 编辑/作废发货批次 | 单次发货批次 | 批次详情 |

## 5. 验收标准

1. 打开订单模块时，默认看到可搜索、筛选的订单列表，不加载任一订单编辑表单。
2. 点击订单后默认进入只读概览；订单编辑只能通过详情页头部的显式`编辑订单`动作进入。
3. 订单级动作固定在详情页右上角，页面内容区域和底部不再散落订单导出、合并导出和编辑按钮。
4. 概览以一行四项紧凑摘要展示订单金额、累计收款、待收款与发货进度；订单商品以含商品、数量、单价、小计和合计的主表展示。
5. 订单档案始终按“客户与订单”“交付与生产”两组关键只读信息展示。
6. 发货页默认显示发货批次列表；每个批次可查看详情并只导出自身的发货清单。订单级不再出现`导出发货清单`。
7. 已生成批次默认只读；编辑必须显式发起；作废替代删除并保留可查询的记录痕迹。
8. 资金页默认显示资金流水，不同时展示收款和冲正两张常驻表单；收款、退款通过独立操作录入。
9. 冲正只能从原流水发起，并保留原流水与冲正流水之间的关联。
10. 列表、概览、发货和资金四个页面中，按钮的所属对象与页面位置符合“订单级、批次级、流水级”边界表。

## 6. 风险与取舍

- **既有历史数据缺少批次或冲正关联信息**：实施前必须盘点当前发货与资金数据是否已有稳定主键及关联字段；不足时应采用兼容迁移或只读降级展示，不能伪造历史关联。
- **作废对库存、累计发货与应收统计的影响**：本方案只确定留痕交互；实施方案必须明确作废后各类累计值的计算口径，并以自动化测试覆盖。
- **订单级导出与发货汇总导出的边界**：必须保留已有订单表导出能力；发货汇总不能取代单批清单，也不能改变已确认的历史清单快照语义。
- **信息密度与窄屏适配**：列表列数和详情档案需在窄视口折叠为主信息优先，不得再次退化成大量空白卡片。
- **范围控制**：本轮不因界面重构而引入会计分录、审批工作流或售后流程重写。

## 7. 待实施调研项

业务设计无待确认项。进入 OpenSpec 前需核实：

1. 当前订单、发货批次、资金流水的 DTO、数据库字段、导出服务和测试覆盖；
2. 既有“合并导出”的业务语义，并决定其是否替换为明确的`导出发货汇总`或保留为订单导出子菜单项；
3. 发货批次作废、资金冲正对统计、导出快照、权限与审计日志的现有实现边界；
4. 订单详情当前编辑页面、弹窗或工作区的实际路由/状态管理方式，以保证本方案不破坏既有返回列表路径。

## 8. 设计确认记录

2026-09-10 已逐项确认：

- 订单概览采用“经营摘要 + 订单档案”的融合结构；
- 订单档案固定为“客户与订单”“交付与生产”两组；
- 发货批次默认只读、显式编辑、作废留痕，发货清单绑定单次批次；
- 资金页采用流水优先，收款/退款独立录入，冲正从原流水发起；
- 订单模块默认入口为列表，整行与明确“查看详情”均可进入详情，编辑不直接出现在每一行。
