## 元数据

| 项目 | 内容 |
| --- | --- |
| 方案版本 | v1.0 |

| 最后修改时间 | 2026-09-09 |

## 1. 目标与背景

当前版本保留了客户、商品、订单、收退款、发货、排班/履约、兼职人员、工资、报表和备份恢复等业务模块，但相较 V1 存在能力缺失、业务语义错误和交互退化。此前的设计也将部分 V1 能力拆分得不符合工作室实际使用方式。

本方案的目标不是新增一组独立功能，而是结合已经确认的业务口径，恢复 V1 核心能力并统一交互：

> 订单能够正确报价、确认、收款、发货和留档；页面默认先看，明确点击新增或编辑后才操作。

本方案结合以下已确认要求：

- 订单表和发货清单是两个独立、正式、可打印、可追溯的业务单据；
- 订单金额由订单明细自动计算，用户界面不再使用“初始确认金额”；
- 缝边是客户针对本订单商品明细决定的服务，不是商品固定客户收费；
- 勾选缝边后，缝边数量默认等于商品数量，但用户可以修改；
- 订单优惠和明细优惠必须纳入订单金额；
- 页面默认只读，点击“新增”“编辑”“登记”后才进入操作态；
- 成功结果使用右上角自动关闭通知，字段错误保留在当前编辑上下文；
- 不做旧 V2 数据迁移，直接使用修正后的新模型。

## 2. 当前已验证现状

### 2.1 订单金额仍使用实现语义

当前订单契约和领域计算使用 `initialConfirmedAmountCents`，新建订单页面显示“初始确认金额（元）”：

- `src/shared/contracts/orders.ts`
- `src/main/domain/order-amounts.ts`
- `src/main/services/v2-order-service.ts`
- `src/renderer/pages/orders/index.tsx`

该字段要求用户直接输入一个金额，没有由订单商品、缝边和优惠自动计算出订单金额，不符合工作室录入习惯。

### 2.2 缝边字段位于商品资料

当前商品契约包含 `edgeCostCents`，商品编辑页面显示“封边（元）”：

- `src/shared/contracts/products.ts`
- `src/renderer/pages/products/index.tsx`
- `src/main/repositories/v2-order-repository.ts`
- `src/main/domain/product-costing.ts`

该字段无法表达“客户本次是否需要缝边、缝多少、协商价格是多少”。

### 2.3 页面存在默认可操作表单

订单详情中存在订单内容变更表单，设置页面的工作室参数也直接呈现输入框。现有多个页面还在页面内容区直接渲染成功或失败反馈：

- `src/renderer/pages/orders/index.tsx`
- `src/renderer/pages/settings/index.tsx`
- `src/renderer/pages/reports/index.tsx`
- `src/renderer/pages/workers/index.tsx`
- `src/renderer/components/settlement/settlement-detail.tsx`

### 2.4 单据已有独立导出设计基础

已有方案 `docs/solutions/2026-09-06-separate-order-and-shipment-exports-solution.md` 明确了订单表与发货清单分离、产品图片、正式表格样式、发货批次快照和历史导出规则。本方案在此基础上补充新的订单金额、缝边和优惠口径，不撤回已经确认的单据规则。

## 3. 范围判断与拆分

这是一个跨订单经营闭环的模块级回归，涉及数据契约、领域计算、订单服务、数据库结构、Renderer 页面、文件导出和全局交互。为降低风险，拆成四个可独立验收的子变更：

1. **订单金额与订单级缝边**：先修正订单报价事实和快照。
2. **浏览优先与全局通知**：统一页面默认状态和结果反馈。
3. **订单表与发货清单**：按新成交快照和发货批次快照恢复正式单据。
4. **其余 V1 经营能力**：恢复预留天数、材料/产能、客户统计、风险报表和收款凭证。

推荐顺序为 1 → 2 → 3 → 4。第 1 项是订单业务事实基础，第 2 项是所有页面的承载规范，第 3 项依赖订单快照，第 4 项可在前三项稳定后分批实现。

## 4. 数据与兼容策略

### 4.1 不做数据迁移

本次变更不对旧 V2 数据提供迁移、字段转换或兼容推算。实施时直接按新模型初始化本地 V2 数据库，测试夹具和演示数据全部重新建立。

明确边界：

- 不读取旧的 `initial_confirmed_amount_cents` 作为新订单金额；
- 不把旧商品 `edgeCostCents` 当作客户缝边售价；
- 不为无新快照的旧发货记录补做历史推算；
- 不保证当前开发数据库中的旧测试数据继续可用；
- 备份恢复能力仍保留，但不承担跨模型迁移职责。

### 4.2 新模型原则

新模型直接表达业务事实：

- 订单金额由订单商品明细计算；
- 客户缝边服务属于订单商品明细；
- 商品资料只维护商品基础资料和必要的内部成本；
- 订单保存时冻结成交快照；
- 发货保存时冻结清单快照；
- 后续变动通过新增记录或调整事实追溯，不覆盖已发生事实。

### 4.3 商品缝边字段

商品资料不再保存客户缝边售价。

如果订单成本核算仍需要内部缝边成本，则保留一个明确命名为“内部缝边成本”的字段，仅参与工作室成本核算；该字段不得作为订单缝边单价默认值、不得作为客户报价、不得出现在客户订单表的收费口径中。

## 5. 订单金额与缝边设计

### 5.1 订单商品明细

每个订单商品明细保存：

```text
商品
商品数量
成交单价
商品金额
是否缝边
缝边数量
缝边单价
缝边金额
明细优惠
明细备注
商品成交快照
```

缝边规则：

- 未勾选缝边时，缝边数量为 `0`，缝边金额为 `0`；
- 勾选缝边后，缝边数量默认等于商品数量；
- 用户可以把缝边数量改为小于商品数量的整数；
- 缝边数量范围为 `1` 至商品数量；
- 商品数量减少导致缝边数量超出时，缝边数量自动收敛到商品数量，并在字段附近说明；
- 缝边单价由本次订单协商填写，允许为 `0`；
- 缝边金额等于缝边数量乘缝边单价；
- 保存后是否缝边、数量、单价和金额全部冻结到订单明细快照。

### 5.2 优惠与订单金额

明细计算：

```text
商品金额 = 商品成交单价 × 商品数量
缝边金额 = 缝边单价 × 缝边数量
明细应收 = 商品金额 + 缝边金额 - 明细优惠
```

订单计算：

```text
订单金额 = 所有明细应收合计 - 订单优惠
已收净额 = 收款合计 - 退款合计
待收金额 = 订单金额 + 金额调整合计 - 已收净额
```

约束：

- 金额全部以整数分保存；
- 单价、优惠和金额不能为负；
- 明细优惠不得使当前明细小于 `0`；
- 订单优惠不得使订单金额小于 `0`；
- 创建订单时不再录入孤立的“初始确认金额”；
- 页面统一使用“订单金额”文案；
- 后续改价、补款、减款使用“订单金额调整”，保留日期、原因和备注。

### 5.3 页面展示

订单详情默认展示：

```text
商品金额
缝边服务费
明细优惠
订单优惠
订单金额
已收净额
待收金额
```

订单列表展示当前订单金额、已收净额、待收金额和资金状态。订单详情不展示成本数字，成本仍通过成本详情入口查看。

## 6. 订单表与发货清单

### 6.1 订单表

入口为：

```text
订单详情 → 操作 → 保存订单表
```

订单表读取订单成交快照，独立保存为 XLSX 文件，内容包括：

- 订单编号、客户姓名、联系方式、收货地址、下单日期；
- 产品图、产品名称、产品克重；
- 成交单价、订购数量、商品金额；
- 是否缝边、缝边数量、缝边单价、缝边金额；
- 明细优惠、明细备注；
- 订单优惠；
- 订单金额和数量合计。

文件必须：

- 仅包含“订单表”工作表；
- 具备正式表格样式、边框、合并单元格和打印设置；
- 有产品图片时嵌入图片；图片失效时留空但继续导出；
- 默认文件名为 `yyyyMMdd-HHmmss-订单表-客户名称.xlsx`；
- 不因导出修改订单、金额或业务状态。

### 6.2 发货清单

入口为：

```text
订单详情 → 履约 → 历史发货批次 → 保存发货清单
```

发货清单绑定一条已保存发货记录，展示订单全部商品：

- 产品图；
- 产品名称；
- 采购总数量；
- 本次发货数量；
- 累计已发数量；
- 未发货数量；
- 商品备注。

本次未发货的商品仍然展示，本次发货数量为 `0`。页尾展示采购总数量、本次发货总数量、未发货总数量、发货时间、收货人、承运商、运单号和发货备注。

发货记录保存时固化完整清单快照。历史清单导出只读取该快照，不因后续发货、订单修改或商品资料修改而改变。

文件必须：

- 仅包含“发货清单”工作表；
- 具备正式表格样式和打印设置；
- 有产品图片时嵌入；图片失效时留空但继续导出；
- 默认文件名为 `yyyyMMdd-HHmmss-发货清单-客户名称.xlsx`；
- 不因导出新增发货记录或改变订单状态。

## 7. 浏览优先交互规范

### 7.1 默认浏览态

页面进入后：

- 只展示业务事实、状态、统计和历史记录；
- 不直接展示可编辑输入框；
- 不自动聚焦字段；
- 不让用户进入页面后无意修改数据；
- 不把复杂创建或编辑表单长期挂在列表下方。

### 7.2 操作态入口

列表页右上角提供实体级新增入口：

```text
新增客户
新增商品
新增订单
新增人员
新增财务记录
```

详情页提供上下文操作：

```text
编辑订单
登记收款
登记退款
新增发货
新增订单变更
新增售后记录
保存订单表
保存发货清单
```

点击后使用弹窗、抽屉或独立编辑区完成操作。保存成功后关闭编辑容器并回到只读查看态；保存失败保留当前输入和上下文。

### 7.3 设置页

工作室参数默认展示只读值和说明，例如：

```text
胶水单价
0.034 元 / 克
```

用户点击“编辑工作室参数”后，才打开编辑容器。保存成功后关闭编辑容器、刷新只读值并显示右上角成功通知。

## 8. 全局通知规范

新增应用级通知容器，由应用壳统一渲染右上角通知栈。页面不得继续为成功结果维护长期占位提示。

| 场景 | 规范 |
| --- | --- |
| 保存、创建、更新成功 | 右上角成功通知，3 秒自动关闭 |
| 订单表、发货清单导出成功 | 右上角成功通知，5 秒自动关闭 |
| 用户取消文件保存 | 右上角信息通知，不提示成功 |
| 保存失败 | 编辑容器内保留错误，可补充右上角错误通知 |
| 字段校验失败 | 字段下方提示，不以 Toast 替代 |
| 删除、恢复、覆盖 | 确认弹窗 |
| 执行中 | 按钮 loading 或区域加载态 |

建议新增：

```text
src/renderer/components/ui/notification/yumi-notification.tsx
src/renderer/components/ui/notification/yumi-notification.test.tsx
```

统一迁移当前设置、报表、人员和工资结算详情中的成功反馈；错误反馈仍保留在最接近错误来源的位置。

## 9. 其余 V1 能力回归

在核心订单闭环稳定后恢复：

1. 预留天数与制作截止日期；
2. 商品材料、损耗和模具产能维护；
3. 客户订单统计与客户历史订单；
4. 商品产能风险报表；
5. 交期风险报表；
6. 部分收款凭证入口、凭证查看和历史关联。

这些能力属于 V1 回归范围，不应被解释为与核心经营无关的新增功能。

## 11. 调用链与状态设计

### 11.1 订单保存

```text
订单新增/编辑入口
→ Renderer 表单计算预览
→ orders composable
→ V2 order IPC
→ v2-order-service
→ 订单金额/缝边/优惠领域校验
→ repository 事务写入订单、订单明细和快照
→ 返回订单详情
→ 关闭编辑容器
→ 右上角显示“订单已保存”
```

失败时：

- 领域校验错误回到对应字段；
- 数据库或 IPC 错误留在编辑容器；
- 不清空表单；
- 不发送成功通知；
- 不留下部分订单数据。

### 11.2 单据导出

```text
订单详情/发货批次操作入口
→ 文件保存对话框
→ 导出 IPC
→ 服务读取订单成交快照或发货批次快照
→ 工作簿构建器生成 XLSX
→ 用户确认保存路径
→ 返回保存结果
→ 成功、取消或失败通知
```

导出不得产生新的订单、发货或金额事实。

## 12. 验收矩阵

| 需求 | 验收结果 |
| --- | --- |
| 订单金额自动计算 | 不输入孤立金额即可由明细、缝边和优惠得到订单金额 |
| 订单级缝边 | 每个订单商品独立选择、填写数量和单价 |
| 缝边默认数量 | 勾选后默认全量，用户可以修改为部分数量 |
| 订单优惠 | 支持明细优惠和订单优惠，金额和快照正确 |
| 订单表 | 独立 XLSX、正式版式、图片、缝边和优惠口径正确 |
| 发货清单 | 绑定发货批次、显示全订单商品和三类数量 |
| 历史清单 | 后续发货和订单变化不改变旧批次清单 |
| 浏览优先 | 页面默认只读，显式点击后才进入编辑 |
| 通知 | 成功提示右上角显示并自动关闭 |
| 错误定位 | 字段错误和保存失败保留在当前上下文 |
| V1 其他能力 | 预留天数、产能、客户统计、风险报表和凭证按阶段恢复 |
| 数据策略 | 不执行旧 V2 数据迁移，测试从新模型初始化 |

## 14. 风险、回滚与非目标

### 风险

- 不迁移旧数据会使当前本地测试数据失效，需要重新建立测试夹具；
- 订单金额模型变化会同时影响资金状态、客户统计、报表和订单表；
- 缝边客户收费与内部成本若命名不清，仍可能被误用；
- 历史发货清单必须严格使用批次快照，否则会发生数量污染；
- 全局通知若承载过多错误信息，会降低错误定位能力，因此错误仍需就地展示。

### 回滚

- 各子变更独立提交，优先回滚 Renderer，再回滚服务与契约；
- 单据导出可以独立停止入口而不删除发货事实；
- 通知系统可暂时退回旧错误展示，但不恢复默认可编辑交互；
- 不通过兼容代码掩盖新模型校验失败。

### 非目标

- 不自动替负责人判断客户/工作室责任；
- 不自动生成返工、补发或收费事实；
- 不因导出单据改变订单或发货状态；
- 不把商品固定售价当作客户最终成交价；
- 不实现旧 V2 数据迁移；
- 不在本方案内改变数据库备份恢复的业务边界。
