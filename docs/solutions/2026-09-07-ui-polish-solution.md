# YUMI 工作台界面巡检与弹窗布局修复方案

- **方案版本**：v1.0
- **设计时间**：2026-09-07
- **最后修改时间**：2026-09-07
- **修改人**：Codex
- **方案状态**：已确认，实施中

## 背景

创建排班弹窗出现内容几乎铺满窗口、输入与任务区域比例失衡、操作区定位不清晰等问题。相同的弹窗和固定宽度策略还可能影响订单、商品、人员、客户和设置页面在较小窗口中的表现。

## 目标

- 保持现有业务逻辑、数据结构和 IPC 接口不变。
- 统一弹窗的宽度、最大高度、滚动和底部操作区布局。
- 修复创建排班弹窗的表单比例、任务行和操作区间距。
- 降低固定最小宽度造成的横向溢出风险。
- 对其他页面做同类 CSS/布局巡检，并用契约测试防止关键样式回退。

## 实施设计

1. 在渲染层增加统一的弹窗内容、弹窗底部操作区和表单布局类；长表单内容在弹窗内部滚动，操作区保持可见。
2. 创建排班弹窗使用稳定的任务行栅格：商品选择占据剩余空间，数量字段保持适中宽度，单位文本不被拉伸。
3. 将额外分钟字段限制在合理宽度，并让弹窗内容在窗口变窄时降级为单列布局。
4. 将应用主体的固定最小宽度改为可收缩布局；需要保持最小内容宽度的日历和报表区域通过局部横向滚动承载。
5. 为上述关键约束增加渲染源代码契约测试，随后执行测试、类型检查、Lint、格式检查和构建。

## 非目标

- 不改动排班计算、订单成本、客户管理或导出逻辑。
- 不新增第三方 UI 依赖。
- 不在本次变更中重做整体视觉主题。

## 验收标准

- 创建排班弹窗在桌面窗口中不再默认铺满宽度，内容和底部按钮区层次清晰。
- 任务选择框、数量输入框和单位文本保持合理比例；窗口变窄时不产生不可控横向溢出。
- 长表单可以在弹窗内部滚动，底部操作按钮仍可访问。
- 其他弹窗和主工作区没有因全局修复出现明显横向溢出。
- 自动化检查全部通过，或明确记录与本次变更无关的既有失败。
