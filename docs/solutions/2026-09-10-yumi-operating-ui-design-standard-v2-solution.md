## 1. 范围

本方案以 YUMI 自定义语义 token 为视觉唯一来源，补齐页面结构、导航层级、术语、操作位置和记录留痕的全局规则。参考稿只用于约束信息层级与交互，不复制其配色；目标不是重新换肤，而是使 YUMI 成为一套可复用、可测试、可持续迁移的经营工作台。

本次包含：

1. 保留已验证的字号、间距、圆角、基础表单和反馈组件能力，颜色统一迁入 YUMI 自定义语义 token；
2. 新增列表页、详情页、记录页和基础资料页的页面模式规范；
3. 区分一级 Tab 与二级 Tab，并禁止用第三层 Tab 继续堆叠；
4. 建立页面级、实体级、记录级、列表级的操作归属规则；
5. 统一“排班”“发货”等业务术语边界；
6. 将订单模块作为第一套端到端验收样板；
7. 对现有共享导航、Tab、按钮、表格、抽屉/弹窗组件进行规范化改造，使其他模块可逐步接入。

本次不包含：

- 深色主题、移动端专用布局、品牌重塑；
- 修改订单、排班、发货、资金、售后等领域数据模型及业务口径；
- 在一个变更中重写所有模块的业务页面；
- 新增权限、审批、库存、会计分录或自动化决策。

## 2. 当前行为

项目已有基础组件体系，已提供页面画布、按钮、字段、标签、表格、抽屉和弹窗等能力；品牌、中性与状态颜色须由 YUMI 自定义语义 token 统一供给。

但当前仍存在以下不一致：

- 一级和二级 Tab 使用同一种“实心选中 + 描边未选中”按钮形态，用户无法判断切换的是页面大类还是局部子视图；
- 页面级、订单级、批次级、流水级动作常被放在同一内容区域或页面底部，业务对象边界不清楚；
- 一些详情页把只读查看与编辑表单并列，商品、流水、批次等主体没有稳定的表格优先阅读方式；
- “履约”同时被用于生产安排和订单交付，词义过大，不能清晰表达用户正在处理的是排班还是发货；
- 已有视觉基础不能自动约束页面的信息层级，导致不同页面继续出现卡片墙、按钮堆和不一致的导航形态。

## 3. 目标设计原则

1. **视觉连续**：维持轻量、专业的 YUMI 经营界面气质；品牌、中性与状态颜色只由独立语义 token 提供，不另起一套皮肤，也不复制参考配色。
2. **经营优先**：高频判断内容先出现；商品、批次、流水等多条事实以表格或列表表达，卡片只用于少量摘要和独立档案组。
3. **层级可见**：导航层级、页面标题、动作等级和记录状态必须仅凭视觉结构即可区分。
4. **对象归属**：动作必须位于所属对象上下文，不能为了方便而上移到无关页面层级。
5. **默认只读**：详情页先展示事实；编辑、冲正、作废等改变数据的动作必须显式发起。
6. **记录留痕**：批次、流水、售后等记录性对象不能静默覆盖或直接删除；更正需关联来源并保留历史。
7. **渐进迁移**：共享规范先落地，订单模块先验收，其他业务页面按同一规则分批迁移，不进行高风险大爆炸重写。

## 4. 设计体系

### 4.1 三层结构

```text
YUMI 经营工作台设计规范 v2
├── 视觉基础层
│   ├── 颜色、字体、间距、圆角、阴影、状态色
│   └── 按钮、字段、标签、表格、抽屉、弹窗、空状态、反馈
├── 经营页面模式层
│   ├── 列表页、详情页、记录页、基础资料页
│   ├── 一级/二级导航层级
│   └── 表格优先、摘要有限、档案分组
└── 业务交互规则层
    ├── 动作按对象归属
    ├── 编辑显式进入
    ├── 批次/流水留痕
    └── 业务术语边界
```

### 4.2 视觉基础层：继承而不重建

保留既有 v1.1 的视觉令牌与组件基线：

- 由语义 token 提供页面画布、内容表面、主/辅助文字、品牌强调与状态表达；
- 4px 间距基准；页面边距 32px、区块间距 20px、面板内部 20px；
- 内容面板 16px 圆角；输入、按钮与常规控件 8px 圆角；筛选和状态标签使用胶囊形；
- 主色仅用于当前主操作、已选状态与关键识别，禁止作为大面积内容背景；
- 成功、警告、危险和中性状态均使用“浅底 + 状态文字”的标签形式；
- 所有交互状态（默认、悬停、禁用、加载、键盘焦点、错误）必须定义在共享组件层，业务页面不得自行拼接样式。

### 4.3 页面模式层

#### 列表页

适用于订单、客户、商品、排班记录、资金/业务记录等需要先搜索与判断的页面。

固定骨架：

```text
页面标题 + 页面说明                         次操作 + 唯一主操作
搜索 / 筛选 / 日期范围 / 批量范围说明
数据表格或经营列表
分页、汇总、空状态或加载状态
```

规则：

- 页面右上角最多突出一个主操作，例如`新建订单`；
- 直接编辑不出现在每个列表行；行点击或明确的`查看详情`进入详情；
- 列表行尾`更多`只用于低频辅助操作；
- 表格列必须围绕此页面的核心判断信息，不能把所有字段平铺；
- 选择范围、状态和日期使用筛选栏，禁止再叠加第三层 Tab。

#### 详情页

适用于订单、人员、排班、发货批次、资金流水等一个明确实体的查看与后续处理。

固定骨架：

```text
返回列表
实体标题 + 关键状态                           次操作 + 唯一主操作
一级 Tab（如有多个实体工作视图）
主体数据表 / 记录列表                         稳定档案或紧凑摘要
局部详情、空状态或最近记录
```

规则：

- 详情默认只读，编辑必须由页头主动作显式进入；
- 页面级操作固定放在详情页头部右侧；
- 商品、任务、批次、流水等可重复的业务事实优先用表格/列表；
- 卡片只用于同类摘要指标、稳定档案或独立的短内容组，禁止用单字段大卡片制造空白；
- 局部记录的动作不得上升为实体级按钮。

#### 记录页与基础资料页

- 记录页（发货、资金、售后）默认展示历史列表，新增和更正通过明确动作打开抽屉或独立页面；
- 基础资料页（财务类目、客户标签等）使用“一级页面导航 + 二级分段视图”，维护动作置于当前子视图的局部页头；
- 删除存在引用的资料应改为停用或受控修改，并显示引用影响。

### 4.4 导航层级规范

#### 一级 Tab：页面/模块切换

一级 Tab 用于模块内大类或实体的主要工作视图切换，例如“工作室参数 / 财务资料 / 数据保护”，或订单详情的“概览 / 发货 / 资金 / 售后”。

样式和行为：

- 文字型横向导航，未选中无按钮描边；
- 当前项使用主文字 + 底部 2px 品牌色指示线；
- 紧贴页面标题或详情头部下方，并以整行底边区分内容区；
- 窄视口允许横向滚动；
- 不使用实心大按钮形态。

#### 二级 Tab：当前页面内的局部视图

二级 Tab 用于当前一级页面内互斥的局部内容，例如“收入类目 / 支出类目 / 私人垫付人”。

样式和行为：

- 使用带极浅背景和细边框的紧凑分段容器；
- 当前项使用品牌色实心小分段，未选项无独立描边；
- 宽度随内容，不占满整行；
- 置于当前一级页面标题/说明之后，明确属于该页面内部。

#### 禁止第三层 Tab

如果一级页面和二级局部视图之后仍需选择状态、范围、日期、视角或对象，必须使用筛选栏、下拉、局部菜单、折叠区或抽屉，不得继续新增第三行 Tab。

### 4.5 操作归属规范

| 层级     | 典型对象             | 动作位置                | 示例                             |
| -------- | -------------------- | ----------------------- | -------------------------------- |
| 列表级   | 一类业务对象         | 列表页头部              | 新建订单、导出订单、搜索、筛选   |
| 实体级   | 一个订单、一个排班   | 详情页头部右侧          | 编辑订单、导出订单、编辑排班     |
| 子记录级 | 一次发货、一次售后   | 对应行或记录详情        | 导出本批清单、编辑批次、作废批次 |
| 流水级   | 一笔收款、退款、冲正 | 原流水行或流水详情      | 查看凭证、发起冲正               |
| 危险级   | 作废、停用、删除     | 原对象上下文 + 二次确认 | 作废发货、停用资料               |

通用规则：

- 每个页面只允许一个视觉主操作；
- 页面级导出不能替代具体记录的单据导出；
- 主操作不等于最危险操作，作废/删除不得使用常规主按钮样式；
- 操作命名必须包含作用对象，例如`导出本批清单`而不是`导出清单`。

### 4.6 术语规范

| 原词/问题      | 统一术语         | 业务边界                             |
| -------------- | ---------------- | ------------------------------------ |
| 全局“履约”     | **排班**         | 生产任务、人员、日期、数量和工作安排 |
| 订单详情“履约” | **发货**         | 发货批次、物流、本批清单、签收与作废 |
| 履约进度       | **发货进度**     | 已发数量 / 应发数量                  |
| 导出履约汇总   | **导出发货汇总** | 订单的发货总览，不能替代单次发货清单 |

术语迁移必须同步更新：导航标题、页面标题、Tab 文案、按钮文案、空状态、帮助文字、测试断言、可访问性标签和导出入口说明。

## 5. 订单模块：首个完整验收样板

订单模块必须完整体现 v2 规范：

1. 默认入口为订单列表；
2. 点击订单进入默认只读的详情概览；
3. 详情页一级 Tab 使用“概览 / 发货 / 资金 / 售后”的下划线导航；
4. 顶部使用紧凑经营摘要、商品主表和双组订单档案；
5. 订单级动作固定在详情页头部；
6. 发货页面以批次列表为主，`导出本批清单`只在对应批次出现；
7. 资金页面以流水列表为主，冲正从原流水发起；
8. 已生成批次和资金流水的修改遵从显式编辑、更正关联与留痕规则。

订单实施完成后，需以订单列表、订单详情、发货批次、资金流水、窄视口 Tab 四类场景作为规范验收基线。

## 6. 迁移与实施边界

建议实施拆分为三个连续阶段：

1. **规范核心**：统一/补齐一级 Tab、二级分段控件、页面头部、动作分级、表格和记录操作的共享组件及样式契约；
2. **订单样板**：依据订单信息架构方案完整改造订单列表、概览、发货、资金与相关文案；
3. **渐进接入**：优先迁移设置-财务资料、全局排班及其他使用多级 Tab 或记录操作的页面；剩余页面按独立任务逐步接入，不阻塞订单验收。

本方案不授权直接实施。进入实施时应在 OpenSpec 中根据实际组件、状态管理、路由、数据契约和测试基线拆成文件级任务；如现有组件已满足规范，应复用而非重复创建。

## 7. 验收标准

1. 一级 Tab 与二级 Tab 在形态、位置和选中态上可一眼区分：一级为下划线文字导航，二级为紧凑分段控件。
2. 任一页面不允许出现第三层 Tab；状态、范围和日期通过筛选栏、下拉或局部菜单处理。
3. 全局导航不再以“履约”指代生产安排，统一使用“排班”；订单详情中原“履约”统一改为“发货”。
4. 页面级、实体级、子记录级和流水级动作符合操作归属表；发货清单只能从具体批次导出，冲正只能从原流水发起。
5. 共用页面头部中只有一个主操作；危险操作不会被渲染为常规主操作。
6. 列表、详情、记录和基础资料页面使用对应模式，不再同时展示历史浏览和无上下文的常驻编辑表单。
7. 订单模块完整通过本规范验收，并成为其他模块改造的组件与交互参照。
8. 视觉令牌、键盘焦点、悬停、禁用、加载、空状态和窄视口导航均有共享组件覆盖与自动化回归验证。

## 8. 风险与待实施调研项

- **既有共享组件命名和覆盖范围**：实施前需确认现有 Tab、页面头部、抽屉、表格和状态标签的真实代码路径及使用页面，避免平行创建另一套组件。
- **术语迁移的历史兼容性**：仅改用户界面和可访问性文案，不擅自重命名领域字段、数据库表、IPC 方法或历史导出文件名；是否需要兼容旧搜索条件由实际契约决定。
- **“排班”与全局“发货”关系**：排班只表示生产安排；订单中的发货批次是交付记录。若未来需要全局发货工作台，应新增明确命名的“发货”页面，不重新引入“履约”泛称。
- **全量迁移风险**：以共享组件收敛 + 订单样板为第一阶段，其他模块分批接入；不得因统一样式阻塞已稳定的业务能力。
- **OpenSpec 范围**：实施前必须基于当前仓库实际代码明确改动文件、测试策略和旧路径兼容方式；本方案不包含任何未经验证的数据模型假设。

## 9. 设计确认记录

2026-09-10 已确认：

- 以“全局设计规范 + 订单模块首批完整落地”推进，不做全量大爆炸重写；

## v2.1 视觉基线修订（2026-09-10）

### 修订原因

桌面人工验收确认：此前实现已覆盖订单的信息架构、交互边界与共享组件，但实际视觉呈现没有达到确认参考稿所体现的页面骨架、信息密度与组件细节。参考稿只作为布局与交互层级的依据，**不得复制其暖粉色配色**。

### 最终视觉原则

1. **颜色独立定制**：YUMI 采用独立的语义色板（画布、中性色、品牌强调、成功/警告/危险/信息），全部页面只能消费 token，不从参考稿提取颜色值，也不允许蓝色、粉色等临时业务页颜色绕过 token。
2. **参考稿还原结构，不复制配色**：订单列表使用“页头 + 筛选工具条 + 业务表格”；详情使用“订单头部 + 四项指标条 + 一级标签 + 内容区”；发货、资金分别使用批次/流水表格作为主体。
3. **数据优先，不使用说明卡填充页面**：商品、批次、流水均优先使用表格或记录行；说明卡仅用于档案摘要、空状态或不可替代的规则提示。
4. **动作按层级归属**：页面级动作固定在页头右侧；对象级动作位于对应表格行或详情；低频动作收入“更多”，不在内容底部散放一组按钮。
5. **视觉验收按截图逐项进行**：在 1440px 及窄屏基线下，逐页对照容器、栅格、表头、行高、辅助信息、状态、动作和空状态；功能测试通过不等于视觉验收通过。

### 页面视觉合同

| 页面     | 必须还原的结构细节                                                             | 不应出现的实现                                         |
| -------- | ------------------------------------------------------------------------------ | ------------------------------------------------------ |
| 订单列表 | 单一业务容器、页头动作、筛选工具条、数量统计、固定列业务表格、进度条和行内动作 | 用通用卡片列表代替订单表；把筛选或导出塞进内容末尾     |
| 订单概览 | 订单头部、四项无间隙指标条、一级文字标签、商品表、两组档案、最近发货           | 大面积空白；指标卡以三列换行；订单级动作落在商品区底部 |
| 发货批次 | 订单级汇总动作、批次表格、批次级导出、状态与物流辅助信息                       | 把“本批清单”放到订单级；以说明卡替代批次列表           |

## v2.2 重新整理设计语言、布局规范与交互规则（2026-09-10）

本次调整不是将截图换一套皮肤，而是以参考稿的**信息层级和工作流**为依据，重新约束全站经营页的视觉语言。颜色不使用参考稿任何色值，由 YUMI 的独立语义 token 提供唯一来源。

### 设计语言

- **色彩**：仅 `tokens.css` 定义画布、表面、文字、边框、品牌、状态、禁用、遮罩和焦点；组件与业务页不得写入十六进制或 `rgba` 色值。
- **层级**：页面由“页标题区、操作区、内容区”构成；一个页面只保留一个主操作，次级操作靠近其所属对象或记录。
- **容器**：列表使用一个连续的业务容器承载工具条和表格；详情使用连续指标条和信息分组，避免为每个数字或说明拆出大卡片。
- **表格**：表头为弱对比表面，行内信息遵循“主信息 + 辅助信息 + 状态 + 所属动作”；金额、日期、进度使用固定列和稳定对齐。
- **标签**：一级视图为下划线文本标签，二级范围切换为胶囊分段标签；两级不可使用相同表现。

### 布局规范

| 场景     | 固定骨架                                            | 密度与内容要求                                                                                |
| -------- | --------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| 订单列表 | 页头 + 筛选工具条 + 固定列订单表                    | 显示订单/客户、下单日期、金额、资金状态、排班进度、预计交付和行内详情动作；筛选结果显示数量。 |
| 订单详情 | 订单头部 + 四项连续指标条 + 一级标签 + 单视图内容区 | 概览优先展示商品表、客户订单档案、交付生产档案和最近发货；不默认进入编辑。                    |
| 发货批次 | 批次标题区 + 批次表                                 | 清单导出只放在批次行；新建发货为页内唯一主操作；批次详情默认只读。                            |
| 资金流水 | 资金标题区 + 汇总条 + 流水表                        | 收款/退款从新增动作进入抽屉；冲正必须从原流水行发起。                                         |

### 交互规则

1. 列表行只负责“查看详情”，创建在列表页头；不把编辑态作为首次进入状态。
2. 一个全局动作只能出现一次；批次导出、冲正、附件等记录动作必须在其记录上下文内出现。
3. 高频查询保持在表格上方，低频录入使用抽屉；提交成功后回到对应记录表，新增记录可直接被看见。
4. 空状态只解释下一步，不用说明卡填补数据区域；有业务记录时，表格优先占据首屏。
5. 所有状态必须用语义标签表达，不能同时依赖颜色和长段说明传递同一含义。

## v2.3 全局应用范围确认（2026-09-10）

### 确认结论

本规范从此作为 **YUMI 全局经营界面规范** 执行。订单不是例外页面，也不是单独换肤试点；订单只是第一套完整样板，用来验证并沉淀全局组件、布局与交互契约。

参考稿只用于提取以下共性：信息层级、内容密度、页面骨架、表格结构、操作位置和查看优先的工作流。**颜色不引用参考稿**；YUMI 通过独立语义 token 管理品牌色、中性色、状态色、焦点、遮罩与阴影。

### 全局页面模式矩阵

| ------------- | ----------------------------------------------------- | ------------------------------------------------------ | -------------------------------------------------------------------------------------- |

### 不可变的全局规则

1. **页面骨架统一**：独立业务页优先使用共享 `YumiPageHeader`、共享操作区、主标签/次级分段、数据表、状态标签、字段、抽屉和空状态；嵌入父页面的记录区使用共享 `YumiSection` 的区块级动作，不得平行造一套同职责组件，也不得重复嵌套页面头。
2. **信息密度统一**：记录型业务数据优先使用连续表格或记录行；禁止用多张大卡片稀释本应一屏可读的信息。
3. **动作层级统一**：每页一个视觉主操作；页面级动作在标题区右侧；对象级动作在行或详情；危险动作不伪装为主操作。
4. **查看优先统一**：从列表进入详情默认只读；编辑必须是有意识的明确切换，不以编辑表单作为详情首屏。
5. **Tab 层级统一**：一级为下划线文字导航，二级为胶囊分段，最多两层；状态、范围和日期只可使用筛选栏、下拉或局部菜单。
6. **实现与验收统一**：样式只消费 token；所有页面同时做桌面和窄屏验收；功能测试通过不代表视觉验收通过。
