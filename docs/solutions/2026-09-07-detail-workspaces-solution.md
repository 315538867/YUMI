# 详情工作区与订单备注展示方案

- **方案版本**：v1.0
- **设计时间**：2026-09-07
- **最后修改时间**：2026-09-07
- **修改人**：Codex
- **对应 OpenSpec 变更**：`refine-detail-workspaces`
- **方案状态**：已完成并验证

## 适用范围

订单、兼职人员和排班的详情查看流程，以及订单创建和编辑时已保存的备注展示。

## 当前行为

- 订单、人员和排班详情均以大型模态窗口承载；详情内同时包含读取、编辑、跳转和业务操作，操作链路较长且受视口尺寸限制。
- 订单详情的数据对象已包含 `notes`，但页面没有渲染该字段，因此创建时填写的备注不可见。
- 订单和人员详情可跳转关联班次或订单，但依赖关闭当前弹窗再打开下一个弹窗。

## 目标行为

- 三类详情在应用主内容区以页面工作区打开，提供清晰的“返回对应列表”操作。
- 订单详情显示非空的订单备注，并保留输入时的换行。
- 查看关联订单或班次时在同一内容区替换目标详情，不出现详情弹窗叠加。
- 新建、编辑、删除确认和填写实际完成数据等短步骤继续保留为弹窗。

## 详细设计

1. App 维护一个 `{ kind, id }` 形式的当前详情目标。打开订单、人员或排班详情时，同时激活对应导航项；返回时清空该目标，展示该导航项的列表。
2. 订单、人员、排班检查器不再包裹在详情 `Dialog.Root` 中，而是渲染为工作区内的详情容器。已有数据加载、保存、刷新和错误处理逻辑保持不变。
3. 详情组件向 App 发出跨详情查看请求；App 替换详情目标，不维护历史栈。返回始终回到当前目标对应的列表。
4. 订单备注使用条件渲染：仅当 `order.notes` 有内容时展示“订单备注”区，并使用 `white-space: pre-wrap` 保留多行文字。
5. 用源代码契约测试防止订单备注遗漏、详情重新变为模态标题，且确保填写完成数据的短流程弹窗不被误删。

## 验收标准

- 打开带备注订单时，主工作区可见“订单备注”及完整备注内容；无备注订单不显示空区块。
- 订单、兼职人员、排班详情不再是详情弹窗，均可返回其列表。
- 详情中的资料保存、状态更新、任务完成登记、编辑和关联详情跳转仍可用。
- 通过组件契约测试、完整测试、类型检查、Lint、构建和 OpenSpec 严格验证。

## 风险与处理

- 统一详情状态可能遗漏调用点：以 TypeScript 检查与组件源代码契约覆盖。
- 从一个详情跳到另一个详情后不提供逐级返回：按已确认范围返回对应列表；若后续需要详情历史，另立变更实现。
- 页面详情内容过宽：在 CSS 约束最大内容宽度，并沿用主工作区滚动能力。
