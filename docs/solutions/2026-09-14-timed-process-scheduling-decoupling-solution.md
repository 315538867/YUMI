# YUMI 计时工序排班解耦与单次核算方案

## 1. 方案结论

本方案采用“只在计划阶段解耦”的方案 C：

- 制作排班继续关联订单商品和数量。
- 捏毛装袋、缝边、打包发货排班只关联员工、日期和工序。
- 工作结束后的核算仍落到具体订单商品，以便推进履约、冻结提成并生成工资依据。
- 制品与非制品统一为“待核算 → 核算一次 → 已核算”，不再要求负责人为系统内部状态重复确认。

核心口径：

```text
排班回答：谁、哪天、做什么工序
核算回答：实际做了多久、产出了多少、落到哪些订单商品
```

## 2. 背景与问题

当前模型把四道工序统一建模为带订单商品和数量的 `process_tasks`。这一模型适合制作，但不适合按实际工时核算的非制品工序：

1. 负责人预排捏毛装袋、缝边或打包发货时必须先选择订单商品和数量，选择困难且不符合现场工作方式。
2. 前道尚未完成或订单可处理数量不足会触发超派提示，阻碍正常预排班。
3. 制作完成数量与质量确认被拆成两次处理，负责人已知产出和合格数量时仍需重复提交。
4. 计时工序先保存核算草稿、再确认工时，形成重复流程。
5. 排班入口分散在订单视角、人员周历和工作安排记录，难以维持一致规则。

## 3. 目标与边界

### 3.1 目标

1. 计时工序可以脱离订单商品自由预排。
2. 制作继续保持订单商品与数量排班及超排校验。
3. 制作一次核算完成产出与质量确认。
4. 计时工序一次核算完成时间、商品产出、履约和工资冻结。
5. 核算记录只有待核算与已核算两种业务状态。
6. 所有新增排班收口到人员周历日期格的“+ 派工”。
7. 保留履约、工资和审计可追溯性。
8. 负责人工作台能够直接发现制作和无任务计时班次的待核算事项。

### 3.2 非目标

1. 不把物流发货批次与“打包发货”计时工序合并。
2. 不允许无排班直接核算；漏排需先在人员周历补排。
3. 不引入多段考勤时间；每次计时核算只有一个连续时间段。
4. 不以预计效率自动扣工资或阻止核算。
5. 本期不接入外部考勤设备，仅保留现有来源扩展能力。

## 4. 统一业务模型

### 4.1 工序分类

| 分类 | 工序 | 排班关联订单商品 | 排班填写数量 | 核算填写时间 | 核算填写产出/质量 |
| --- | --- | --- | --- | --- | --- |
| 制品 | 制作 | 是 | 是 | 否 | 实际产出、合格数量 |
| 非制品计时 | 捏毛装袋 | 否 | 否 | 是 | 订单商品完成数量 |
| 非制品计时 | 缝边 | 否 | 否 | 是 | 订单商品完成数量 |
| 非制品计时 | 打包发货 | 否 | 否 | 是 | 订单商品完成数量 |

“返工”和“售后补发”仅允许用于制作工序。非制品计时工序的核算商品必须来自当前工序真实可处理数量，不通过任务来源制造额外数量。

### 4.2 状态模型

负责人可见的核算状态统一为：

```text
待核算 ──核算──> 已核算
```

- 待核算：存在有效排班，但尚无有效核算记录。
- 已核算：已经生成有效履约和工资依据。
- 更正、作废是已核算记录上的操作，不是额外核算状态。
- 作废后原记录保留审计状态，对应排班重新表现为待核算。

## 5. 排班设计

### 5.1 制作排班

制作排班继续保存：

- 员工
- 日期
- 订单商品
- 计划数量
- 额外预留分钟（沿用现有制作规则）
- 来源
- 备注

创建和编辑时继续检查订单需求、其他有效已排和本次计划数量。未确认超排风险时不得保存。

### 5.2 计时工序排班

计时排班只保存：

- 员工
- 日期
- 工序
- 备注

不保存：

- 订单
- 商品
- 计划数量
- 计划分钟
- 计划开始/结束时间

规则：

1. 日期可为过去、当天或任意未来日期。
2. 同一员工、同一日期、同一计时工序最多有一条未取消排班。
3. 计时排班不创建 `process_tasks`。
4. 计时排班不占用订单商品可处理数量，不计算已派、待派和超派。
5. 请假、缺勤或取消只影响该公共工序班次，不释放某个订单商品数量。

## 6. 排班界面与入口

### 6.1 排班菜单

沿用现有周历布局并作以下调整：

- 删除“订单视角”页签。
- 默认进入“人员周历”。
- 保留“待核算”页签。
- 保留顶部统计概览、上周/本周/下周、七天日期列和“导出排班”。
- 保留每个日期格中的“+ 派工”。
- 不新增右上角全局“新建工作安排”。

点击日期格“+ 派工”后预填日期：

- 选择制作时展示订单商品、数量、来源、额外分钟和备注。
- 选择计时工序时只展示员工、日期、工序和备注。

### 6.2 其他页面

订单详情、人员详情、待核算、已核算记录和其他工作台不得直接创建排班。需要排班时只能“前往排班”，导航可带入员工、日期、工序和目标周，但不得自动创建或自动打开新建表单。

订单详情只展示订单自身的履约进度，不展示“某人将在某天处理这个订单商品的计时工序”，因为计时排班不属于具体订单。

### 6.3 工作安排记录

移除右侧“新建工作安排”。该页面仅负责：

- 查询安排记录
- 查看详情和状态
- 查看核算状态与关联核算记录

新增、编辑、取消排班统一回到排班菜单处理；实际产出与工时统一进入待核算流程处理。

### 6.4 周历卡片

- 制作卡片继续显示订单商品、计划数量和处理状态。
- 计时卡片只显示“工序 · 待核算”或“工序 · 已核算”，不显示商品名。
- 排班日期不晚于本地今天的待核算卡片可打开并预填员工、日期、工序的核算表单；未来日期卡片只打开安排详情。
- 点击已核算制作或计时卡片打开记录详情，并在未锁定时提供更正、作废。

## 7. 制品一次核算

制作核算表单一次填写：

- 实际产出数量
- 合格数量
- 备注（可选）

系统计算：

```text
不合格数量 = 实际产出数量 - 合格数量
未完成数量 = 排班数量 - 实际产出数量
```

约束：

```text
0 ≤ 合格数量 ≤ 实际产出数量 ≤ 本次排班数量
```

本方案明确不允许一项制作核算超过本次排班计划，避免超额产出占用其他有效制作排班已经计划的订单需求；确有超计划产出时，应先调整尚未核算的计划或补建制作安排。实际产出可以为 0，用于如实确认当班无产出并关闭待核算事项；零产出不生成履约、计件工资或材料扣款数量。

一次确认在同一事务中完成：

1. 保存制作完成结果。
2. 保存合格和自动计算的不合格质量事实。
3. 合格数量进入待捏毛装袋。
4. 不合格数量不进入下一工序，并保留制作返工依据。
5. 未完成数量重新表现为订单商品待制作缺口。
6. 冻结制作提成与材料扣款依据。
7. 将任务及安排更新为相应已核算状态。

负责人不再先提交完成数量、再进入待质检，也不填写不合格数量。

## 8. 非制品计时一次核算

### 8.1 核算前提

- 必须存在员工、工作日期和计时工序一致的有效排班。
- 同一员工、同一开始日期、同一计时工序最多存在一条有效核算。
- 没有排班时只提示前往人员周历补排，不提供核算面板内快捷创建。

### 8.2 实际时间范围

负责人填写一个连续时间段：

- 实际开始时间
- 实际结束时间

不手工输入分钟。系统以绝对时间差计算正整数分钟。

规则：

1. 支持跨日。
2. 工作日期和工资期间按开始日期归属，不按零点或自然周拆分。
3. 开始日期必须等于排班日期。
4. 结束时间必须晚于开始时间。
5. 当前时间早于结束时间时禁止确认。
6. 排班日期不晚于本地今天即可打开核算；系统不在打开前判断班次是否已经结束，最终以提交时填写的实际结束时间校验。

### 8.3 订单商品候选

候选不再来自 `processTaskId`，而是根据所选工序直接检索当前可处理的订单商品。

每行展示：

- 客户
- 订单号
- 商品
- 交期
- 当前可处理数量
- 完成数量

排序：

1. 已逾期订单。
2. 有交期订单按交期升序。
3. 同交期按订单创建时间升序。
4. 无交期订单置后。
5. 最后按订单号和订单商品顺序稳定排序。

勾选时默认将完成数量填为最新可处理数量，负责人可以修改。手工修改后，候选刷新不得覆盖；取消选择清除输入，再次选择使用最新可处理数量。

### 8.4 确认校验

界面提供即时校验，主进程在事务内重新读取并校验：

```text
0 < 完成数量 ≤ 当前工序可处理数量
```

缝边还必须满足订单商品已选择缝边且完成数量不超过剩余缝边需求。可处理数量为零的商品不得出现在候选中。

### 8.5 确认结果

负责人点击一次“确认核算”后，系统在同一事务中：

1. 冻结工作日期生效的个人时薪。
2. 为每个商品冻结该工序提成和单件预计分钟快照。
3. 根据订单商品和完成数量直接生成履约事件。
4. 保存实际开始、结束和系统计算分钟。
5. 生成可被工资结算引用的已核算来源。
6. 将对应排班表现为已核算。

不再提供“保存草稿”“保存并确认”“确认工时”。关闭未提交表单时可以提示未保存，但不会生成业务记录。

## 9. 工资和效率口径

### 9.1 计时工资

```text
计时工资 = 实际分钟 ÷ 60 × 冻结个人时薪
计件提成 = Σ（商品完成数量 × 冻结商品工序提成）
应计来源 = 计时工资 + 计件提成
```

捏毛装袋和缝边可包含时薪与提成；打包发货沿用当前仅时薪口径。

### 9.2 预计指标

```text
预计总分钟 = Σ（商品完成数量 × 冻结单件预计分钟）
时间差 = 实际分钟 - 预计总分钟
预计效率 = 预计总分钟 ÷ 实际分钟
```

预计总分钟、时间差和预计效率只展示，不阻止确认，不自动扣工资，也不改写履约数量。

## 10. 更正、作废与审计

### 10.1 未被锁定的记录

制作和计时已核算记录都提供更正与作废。当履约产出尚未被下游消耗且核算尚未进入已确认工资结算时：

- 更正：填写原因并提交新内容；系统在同一事务中撤销旧质量、履约和工资来源、保留旧版本并建立新版本，最终仍为已核算。
- 作废：填写原因；系统撤销适用的质量、履约和工资来源、保留作废记录，对应排班重新成为待核算。
- 已进入工资结算草稿：取消旧草稿来源并重新计算草稿中的计时工资、制作计件、材料扣款和总金额。

负责人不需要手动先作废再重录。

### 10.2 已被锁定的记录

若产出已被下游工序或发货消耗，或者工时已进入已确认工资结算：

- 不得直接删除或改写历史事实。
- 履约数量差异通过独立履约调整处理。
- 已结算工时差异通过后续工资结算调整处理，并继续使用原冻结时薪。
- 界面明确说明阻止原因和可继续处理的入口。

## 11. 数据与服务设计

### 11.1 工作安排

继续使用 `work_assignments` 作为班次事实：

- 制作安排包含一个或多个 `process_tasks`。
- 计时安排允许没有 `process_tasks`。
- 数据库增加计时工序未取消排班的员工/日期/工序唯一约束。

### 11.2 计时核算

`work_time_reviews` 保存：

- 员工
- 开始日期
- 工序
- 实际开始/结束时间
- 系统计算分钟
- 时薪快照
- 有效/作废及更正链信息

`work_time_review_items` 改为以 `order_item_id` 表达商品完成事实，并保存：

- 完成数量
- 提成快照
- 单件预计分钟快照
- 履约事件来源关联
- 必要的历史任务兼容标识

履约事件增加确定性的 `source_event_key`。新核算事件以“来源类型 + 来源记录 + 事件键”唯一，捏毛装袋向缝边和打包分流时使用不同事件键，使一个核算明细可以合法生成多条事件，同时阻止重试重复写入。

确认、作废和更正必须在 SQLite 事务内完成，防止只写入履约或只写入工资来源。

### 11.3 制作核算

主进程提供制作原子核算入口，由服务层在一次事务中创建完成结果和质量事实。`process_results` 允许零完成数量，并作为制作核算版本根保存有效/作废状态、替代版本、原因和时间；每项制作任务最多只有一条当前有效结果。制作更正和作废必须同步处理质量事实、履约事件、制作工资和材料扣款来源。旧的两步方法可保留为内部兼容读取，但新界面和新 IPC 不再串行调用两次。

### 11.4 负责人工作台

负责人工作台直接从制作任务和计时公共班次投影待核算事项。计时事项不得依赖 `process_tasks`；制作事项不得依赖新的 `pending_inspection` 中间状态。点击事项统一进入排班菜单待核算视图并定位对应安排，返回时保留原工作台上下文。

## 12. 迁移策略

1. 新增下一版本 SQLite migration，不修改已经执行的历史 migration。
2. 为计时核算商品明细补充订单商品主关联、提成和预计分钟快照字段。
3. 调整制作结果约束以允许零产出，并增加制作核算版本、作废和替代关系字段。
4. 为履约事件增加可空事件级幂等键；历史事件不补写、不重放。
5. 保留既有已确认、已作废记录及其来源关系可读。
6. 新代码不得为旧记录重复生成履约事件或工资来源。
7. 既有草稿不再作为业务状态继续流转；迁移时标记为作废历史并释放对应排班，使其重新进入待核算。
8. 草稿工资结算中的核算来源在更正或作废时必须取消并重算；已确认结算保持原值。
9. 新增目标结构守卫，确保关键时间范围、商品快照、制作版本和事件幂等列存在。
10. 回滚应用版本前必须恢复升级前数据库备份；不允许新旧版本同时写同一数据库。

## 13. 验收标准

### 13.1 排班

- 人员周历是排班默认视图。
- 订单视角不存在。
- 只有人员周历日期格“+ 派工”可以创建安排。
- 工作安排记录不显示“新建工作安排”。
- 计时排班不要求订单、商品或数量，且不会触发订单超派提示。
- 制作排班规则保持不变。

### 13.2 制品核算

- 一次输入实际产出和合格数量即可完成核算。
- 不合格与未完成数量由系统计算。
- 允许零产出并且不生成履约、计件工资或材料扣款数量。
- 实际产出不得超过本次制作排班计划。
- 不再出现待质检二次处理入口。
- 履约数量、制作工资和材料扣款保持守恒。

### 13.3 非制品核算

- 一次输入时间范围和多商品完成数量后直接已核算。
- 不显示手工分钟、草稿或确认工时按钮。
- 支持跨日并按开始日期归属。
- 候选排序、默认数量和双层可处理数量校验正确。
- 核算后履约、工资和快照同时生成。

### 13.4 审计与工作台

- 重复核算不重复履约或计薪，捏毛装袋分流事件能够共存。
- 制作和计时可回退记录都能够原子更正或作废。
- 草稿工资结算在核算更正或作废后取消旧来源并重算。
- 已被下游或已确认结算锁定的记录不能静默改写。
- 所有更正与作废保留原因、旧版本和关联关系。
- 无任务计时班次仍会出现在负责人工作台待核算事项中。
