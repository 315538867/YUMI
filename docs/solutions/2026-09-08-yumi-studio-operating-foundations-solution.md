# YUMI 工作室经营基础重构方案

- **版本**：v1.0
- **状态**：已确认，实施中
- **日期**：2026-09-08
- **关联 OpenSpec**：`strengthen-studio-operating-foundations`

## 1. 背景与目标

本轮不以“补几个页面”为目标，而是修正影响日常操作、成本口径和数据安全的四个基础问题：

1. 应用外壳滚动边界错误，左侧导航会随右侧内容被撑高；
2. 已具备后端能力的数据备份、恢复入口未在设置中提供；
3. 商品被错误建模为手填“原材料成本/制作胶水成本”，遗漏了工作室统一胶水单价与商品克重；
4. 各层仍可能自行用 `number` 计算金额，无法保证 `0.0034 元/克` 这类高精度费率在前后端、订单快照、扣款和报表中的一致性。

目标是让负责人只维护一次工作室胶水单价；商品录入自身克重；每张订单冻结当时的克重与胶水单价；所有最终金额按统一规则精确计算和入账。同时将“人员与时薪”改成以人员列表和按需侧栏为中心的管理体验。

## 2. 已确认业务规则

- 工作室只有一个**统一胶水单价**，录入单位为元/克，允许精确到 `0.000001` 元/克；例如 `0.0034` 元/克必须完整保存。
- 商品仅维护自身胶水克重，可精确到 `0.001` 克；创建/编辑商品时展示当前工作室胶水单价，但不允许在商品内覆盖。
- 商品胶水成本由“商品克重 × 工作室胶水单价”推导，不再录入“原材料成本”或“制作胶水成本”。包装、配饰、替换袋、封边等仍为逐件金额。
- 创建订单时冻结商品克重、胶水单价和其它成本字段；之后修改工作室单价或商品克重，不得改变历史订单、质检扣款、工资结算和报表。
- 金额计算在汇总到应入账金额时才按**四舍五入（HALF_UP）到分**；不得先把单件胶水金额舍入后再乘数量。
- 负责人输入“元”的普通金额只接受最多两位小数；胶水单价和克重使用各自允许的精度。所有非法精度或负数必须返回可见错误，不能静默截断。
- 人员与时薪默认只展示人员列表；新建人员、查看人员资料、调整时薪均在按需侧栏中完成，避免一个页面同时堆叠多个表单与列表。
- 左侧导航和顶部栏固定于窗口；仅右侧内容区域滚动。窗口高度不足时，左侧导航自己滚动。
- 设置采用互斥工作模式：`工作室参数`、`财务资料`、`数据保护`。数据保护提供立即备份、备份历史、恢复确认；恢复前必须提示系统会先创建安全备份，恢复后重启应用。

## 3. 金额与精度模型

### 3.1 统一金额内核

新增共享模块 `src/shared/money/`，由渲染进程与主进程共同引用，并使用 `decimal.js` 进行十进制解析、乘除与舍入。业务页、IPC、Service、Repository 和报表不得直接用 `Number()`、浮点乘法或 `Math.round()` 计算金额。

| 数据 | IPC / 领域字段 | SQLite 存储 | 输入精度 |
| --- | --- | --- | --- |
| 实际金额 | `Cents` 整数分 | `INTEGER` | 元，最多 2 位小数 |
| 胶水单价 | `GluePriceMicroYuanPerGram` | `INTEGER` | 元/克，最多 6 位小数 |
| 商品克重 | `WeightMilligrams` | `INTEGER` | 克，最多 3 位小数 |

`0.0034 元/克` 保存为 `3400` 微元/克；`25 克` 保存为 `25000` 毫克。总胶水成本按整数单位精确换算，并仅在最终需入账的金额边界转为分。

### 3.2 舍入边界

- 单件预览可展示高精度参考金额，例如 `¥0.085 / 件`；
- 多件订单、质检不合格扣款、报表成本使用“总克重 × 单价”后一次舍入至分；
- 所有已有 `Cents` 金额汇总仍以整数分相加；
- 负向金额（调账、扣款）遵循相同 HALF_UP 规则；
- 文本输入先由共享模块验证，再在 IPC/service 复核，前端验证不是唯一边界。

## 4. 数据与兼容策略

新增迁移版本：

1. `app_settings` 中维护 `studio.gluePriceMicroYuanPerGram`，不存在时按 `0` 初始化；
2. `products` 新增 `glue_weight_milligrams`，保留旧成本列以兼容已有数据库读取，但新建/更新不再依赖旧的手填胶水成本；
3. 产品订单快照新增克重与胶水单价；所有新订单使用完整快照；
4. `process_tasks` 和质检扣款从订单快照计算胶水成本，确保在历史订单中的单价保持稳定；
5. 测试数据可按新模型重建；真实历史数据升级时保留旧字段，缺少新快照的历史记录继续读旧整数分字段，绝不擅自重算或改写历史结算。

## 5. 交互设计

### 5.1 固定应用外壳

应用根节点锁定为视口高度。左栏与顶部栏不参与主内容滚动；右侧内容容器为唯一纵向滚动容器。小屏下左栏仍可折叠为图标模式，但保留独立导航滚动。

### 5.2 设置

- 页面标题“设置”仅保留一次；
- 顶部模式切换互斥显示一个工作区；
- `工作室参数`：一个紧凑设置卡，展示当前胶水单价、单位与保存按钮；
- `财务资料`：复用现有动态类目与垫付人能力；
- `数据保护`：顶部状态与“立即备份”，下方仅保留备份历史列表；点击恢复打开二次确认侧栏。

### 5.3 商品

商品列表保持默认视图。新建/编辑抽屉内将“成本”拆为：

- 胶水：工作室单价（只读）+ 商品克重（可编辑）+ 计算预览；
- 逐件其他成本：包装、配饰、替换袋、封边；
- 制作：标准时长、制作提成。

删除手填“原材料成本”和“制作胶水成本”字段，避免负责人把同一成本重复录入。

### 5.4 人员与时薪

- 默认页只展示人员列表及“新增人员”；
- 点击一位人员打开资料侧栏，展示当前时薪、备注与历史；
- 侧栏内“调整时薪”进入局部编辑态，提交成功后原地刷新历史；
- 新建人员在同类侧栏填写姓名、首个时薪、生效日期与备注；
- 不在列表页并列显示新建表单、时薪表单、历史卡和列表。

## 6. 非目标

- 不引入原料库存管理；
- 不把日常收支强制关联订单；
- 不改变负责人对售后责任、最终工资和退款的裁量权；
- 不将备份恢复替换为 Excel 导入；Excel 仍仅是报表导出能力。

## 7. 验收矩阵

| 验收点 | 验证方式 |
| --- | --- |
| 左栏固定、右侧独立滚动 | DOM/CSS 回归测试 + 调试实例人工检查 |
| 备份、历史、恢复确认可用 | IPC/页面测试；恢复调用必须要求 `confirmed: true` |
| `0.0034 × 25 × 100 = ¥8.50` | 共享金额模块和服务测试 |
| 不先单件舍入 | `¥0.085 × 100 = ¥8.50` 回归测试 |
| 新订单冻结单价与克重 | 订单服务与迁移测试 |
| 缺陷胶水扣款来自历史快照 | 履约/结算服务测试 |
| 人员页面无并列编辑表单 | 渲染测试 + 人工检查 |
| 所有金额入口统一校验 | 共享模块单测、IPC/service 边界测试、类型检查 |
