# YUMI 运营界面操作流重构方案

## 已确认的核心规则

- 列表页负责找和看。
- 创建页负责录入；订单和商品不使用长期并列小表单。
- 详情页负责后续处理；订单详情承载资金、分批发货、售后等动作。
- 基础资料页负责维护客户、商品、人员、时薪、类目和垫付人。
- 负责人保留对售后、收费、排班和实际发放的决定权，界面不得把这种裁量改成系统自动决策。

## 页面结构

- 订单：订单列表 / 新建订单 / 订单详情。
- 履约：全局待办队列 / 单订单履约处理。
- 工资：工资结算 / 人员与时薪。
- 财务：经营概览与流水 / 按需登记收支 / 待报销。
- 基础资料：客户、商品、设置。

## 实施阶段

1. 应用壳与订单工作流。
2. 全局履约待办。
3. 客户、商品、工资、财务的按需表单。
4. 样式、全量验证和桌面端人工检查。

## 不在本次范围

不引入库存、云同步、账号权限或新的自动业务决策；不修改 V2 数据库 schema 和既有领域口径。
