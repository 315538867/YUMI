# 移除固定成本分摊设置与计算方案

- 方案版本：v1.1
- 设计时间：2026-09-06
- 最后修改时间：2026-09-06
- 修改人：Codex
- 关联 OpenSpec：`remove-configurable-target-effective-minutes`
- 提案名称：移除固定成本分摊
- 当前实施状态：已完成

## 1. 背景

用户确认“月度固定成本”和“目标有效工时”不参与当前工作室的实际决策。两项设置只会推导出固定成本时薪，并叠加到商品、订单与产能报表的预计成本，容易让用户误认为它们会影响排班、兼职人员工资或实际结算。

## 2. 目标与边界

### 目标

1. 从系统设置中移除月度固定成本和目标有效工时。
2. 从商品成本预估、订单预计成本、商品成本报表中移除固定成本分摊。
3. 保留胶水单价和默认兼职时薪，继续参与预计成本。
4. 保持兼职人员实际工时与按件提成结算不变。

### 非目标

- 不删除历史订单，也不回算其已保存的预计成本。
- 不物理删除 SQLite 历史表中的旧列，避免破坏已存在的本地数据库；业务读取会忽略旧字段；新记录仅为兼容 SQLite 表结构而写入占位值，不参与计算。
- 不修改排班、模具产能、订单已排/未排、实际生产成本和人员结算。

## 3. 设计决策

### 3.1 从业务契约移除固定成本字段

`CostSettings`、更新输入、商品成本预览结果和订单商品快照不再包含月度固定成本、目标有效工时及固定成本时薪。商品成本领域计算不再接收或产生固定成本分摊。

### 3.2 兼容既有 SQLite 表结构

`cost_settings_history` 中的历史列暂不执行破坏性删除。保存新的成本设置记录时，为旧列写入安全占位值：月度固定成本为 `0`、目标有效工时为 `9600`、固定成本时薪为 `0`；业务读取只使用胶水单价和默认兼职时薪。

### 3.3 历史订单保持不变

旧订单的 JSON 快照和预计成本不做回算。今后新建或更新的订单不再保存或计算固定成本分摊，保证新的成本口径清晰且不篡改历史数据。

## 4. 验收标准

1. 设置页不再显示月度固定成本和目标有效工时，仅保留胶水单价、默认兼职时薪与生效日期。
2. 商品成本预览和订单预计成本不包含固定成本分摊；总成本不再叠加该部分。
3. 新订单快照不包含固定成本时薪；旧快照可继续读取。
4. 商品成本与产能报表的单位预计成本不再含固定成本。
5. 类型检查、lint、全量测试、构建和 OpenSpec 严格校验通过。

## 5. 实施与验证结果

- 已从共享成本设置、商品成本预览和订单商品快照契约中删除固定成本字段；领域总成本仅保留材料、包装、默认兼职人工和按件提成。
- 已保留 `cost_settings_history` 的旧列：新记录写入 `0 / 9600 / 0` 兼容值，读取时只使用胶水单价与默认兼职时薪。
- 已移除设置页的月度固定成本、目标有效工时，以及商品预览中的房租水电分摊；实际兼职人员结算逻辑未变。
- 已验证：`npm run typecheck`、`npm run lint`、`npm run build`、`openspec validate remove-configurable-target-effective-minutes --strict` 和 `git diff --check` 通过；在本地 Electron 调试运行时以 Electron Node 运行完整 Vitest 套件，28 个测试文件、85 个用例全部通过。

## 6. 运行时说明

当前本地调试使用 Electron ABI 的 `better-sqlite3` 原生模块。为避免 `npm test` 的 `pretest` 脚本切换到系统 Node ABI 并覆盖正在运行的 Electron 原生模块，本次全量测试使用 Electron Node 直接执行同一 Vitest 套件。
