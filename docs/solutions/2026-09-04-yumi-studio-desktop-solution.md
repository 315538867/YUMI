# YUMI 工作室管理桌面应用方案

## 1. 目标与范围

YUMI 是供捏捏工作室内部使用的单电脑、离线优先桌面管理工具。系统将订单、商品成本、兼职制作、模具批次产能和日历排班串成一条可追溯的工作流，帮助工作室掌握交期、收款、成本和产能风险。

### 第一期目标

- 管理商品种类、商品售价与成本参数。
- 管理客户、订单、订单商品明细以及多次收款和退款。
- 以预计发货日期和预留时间约束制作排班。
- 直接在日历中为兼职人员创建实际上班时间段。
- 将排班任务绑定到订单商品和计划制作数量。
- 同时校验人工时长、商品模具数量和每日批次数限制。
- 登记缺勤、实际完成数量、人工时薪成本和按件提成。
- 本机 SQLite 存储，支持备份、恢复与 Excel 导出。

### 第一阶段不做

- 多人账号、多电脑同步、云端协作、移动端。
- 兼职人员自行申报可工作时间。
- 复杂 CRM、营销自动化、供应商采购、库存管理和会计报税。
- 根据固化或制作时间自动推算每日批次数。

## 2. 关键决策

| 主题     | 已确认决策                                                     |
| -------- | -------------------------------------------------------------- |
| 应用形态 | Electron 桌面应用，单电脑、本地离线使用                        |
| 前端技术 | React + TypeScript                                             |
| 基础组件 | Radix Themes；建立 YUMI 自定义主题，不套网页后台模板           |
| 视觉方向 | 简约大气，参考 Linear 的秩序与紧凑度，使用温暖低饱和配色       |
| 数据库   | SQLite，数据库与附件保存在本机应用数据目录                     |
| 本地后端 | Electron Main 作为本地后端，Renderer 不直接操作数据库          |
| 商品模型 | 商品种类资料库；订单商品明细保存价格和成本快照                 |
| 兼职提成 | 商品固定的单件提成，按合格完成数量结算，不因兼职人员而异       |
| 缝边     | 商品级可选增值收费；不同商品默认缝边单价不同                   |
| 排班     | 日历时间轴；直接创建人员上班时间段并绑定订单商品任务           |
| 产能     | 人工工时与模具批次产能双重约束；第一期每日批次数手动填写       |
| 风险校验 | 超工时、未满工时、模具超产能、超交期均弹窗确认，不强制阻止保存 |

## 5. 商品管理与成本

### 5.1 商品字段

```text
商品名称、商品编号、商品分类、商品图片、启用状态、备注
默认销售单价
默认缝边收费（每件）
单件材料重量（克）
损耗率（百分比）
标准制作时长（分钟/件）
单件包装成本
单件兼职提成
模具数量
单模具每批产出数量，默认 1
每日最大批次数，手动填写
```

### 5.2 预计成本公式

设订单商品数量为 `Q`：

```text
预计胶水用量（克）
= Q × 单件材料重量 × (1 + 损耗率)

预计胶水成本
= 预计胶水用量 × 胶水单价（元/克）

预计人工工时（小时）
= Q × 标准制作时长 ÷ 60

预计人工提成
= 合格完成数量 × 商品单件提成

包装成本
= Q × 单件包装成本
```

人工时薪成本在排班和实际完成后按对应人员时薪计算。

### 5.3 固定成本分摊

房租、水电和其他固定支出使用按标准生产工时分摊的规则：

```text
月度固定成本 = 房租 + 水电 + 其他固定支出
工作室固定成本时薪 = 月度固定成本 ÷ 当月目标生产工时
订单商品分摊固定成本 = 商品数量 × 标准制作时长 ÷ 60 × 工作室固定成本时薪
```

每月维护固定成本与目标生产工时。订单创建时将当期固定成本时薪写入成本快照，后续修改设置不改变历史订单利润。

### 5.4 缝边规则

缝边是客户选择的可选增值收费：

```text
商品基础售价：39 元/件
默认缝边收费：3 元/件
订单数量：10 件
客户选择缝边：是

商品明细应收 = 39 × 10 + 3 × 10 = 420 元
```

订单商品明细保存是否缝边、缝边数量、缝边单价和缝边收费合计的快照。第一期不为缝边创建独立排班任务；日后如需要核算额外时间或内部成本，可增加对应参数。

## 6. 客户、订单和收付款

### 6.1 客户档案

客户采用轻量资料库：

```text
客户昵称或姓名、联系方式、常用收货地址、备注
历史订单、累计消费、最近下单日期
```

创建订单时可选择已有客户，也可直接录入并自动建档。订单保留客户资料快照，客户资料变更不影响历史订单。

### 6.2 订单字段

```text
订单编号、客户、下单日期、订单状态
预计发货日期、预留天数、最晚完成制作日期
订单商品明细、商品金额、缝边服务费、优惠或改价
应收金额、已收净额、待收金额
备注、附件与收付款凭证
```

### 6.3 订单状态

制作流程：

```text
待确认 → 待排班 → 制作中 → 待发货 → 已完成
                     └→ 已取消
```

资金状态由流水自动计算：

```text
未收款、部分收款、已结清、退款中、已退款、超收
```

制作状态和资金状态彼此独立。

### 6.4 收款和退款

每个订单可以有多条流水：定金、补款、尾款、取消退款、部分退款或售后退款。

```text
已收净额 = 收款合计 - 退款合计
待收金额 = 订单应收金额 - 已收净额
```

每笔流水记录日期、金额、支付方式、备注、凭证和操作人。

## 7. 发货日期、风险预留和交期

订单维护预计发货日期和预留天数：

```text
最晚完成制作日期 = 预计发货日期 - 预留天数
```

系统判断交期时，需要同时检查最晚完成制作日期之前：

- 已排产数量是否足够；
- 已排人工时间是否足够；
- 商品每天的剩余模具批次产能是否足够。

预留时间用于处理质检、包装、返工、缝边、临时缺勤等风险。系统设置中提供默认预留天数，每个订单允许单独覆盖。

## 8. 日历排班、模具产能和异常处理

### 8.1 排班视图

排班模块默认使用按人员分组的周视图时间轴：

- 横向为日期；
- 纵向为兼职人员；
- 每个排班块显示时间、订单商品、计划数量、预计工时和风险；
- 月视图展示每日产能、订单交期和风险数量；
- 右侧检查器显示选中排班详情、订单商品进度和商品当天模具占用。

### 8.2 排班对象

```text
Shift：兼职人员某天的上班时间段
ShiftTask：该时间段内负责的一个订单商品任务
```

一个 Shift 可包含多个 ShiftTask。例如：

```text
小A，2026-09-08，10:00–14:00
- 草莓蛋糕捏捏：4 件，预计 2 小时
- 小熊捏捏：4 件，预计 2 小时
```

### 8.3 创建排班

1. 在周历中选定兼职人员、日期和起止时间；
2. 添加一个或多个任务；
3. 每个任务必须选择订单、商品和计划制作数量；
4. 系统计算任务预计时长和商品当天模具占用；
5. 显示风险提示并保存。

### 8.4 时间校验

```text
排班时段可用分钟数 = 结束时间 - 开始时间
任务预计分钟数 = 计划数量 × 商品标准制作时长
时段总预计分钟数 = 所有任务预计分钟数之和
```

### 8.5 模具与批次产能

```text
单批最大产能 = 模具数量 × 单模具每批产出
每日模具最大产能 = 单批最大产能 × 每日最大批次数
```

示例：20 个模具、每模具每批 1 件、每日 2 批，则商品日产能为 40 件。

同一商品在同一天的不同订单共享日产能：

```text
订单 A 计划 25 件
订单 B 计划 20 件
当日总计划 45 件
当日最大产能 40 件
→ 模具产能超出 5 件
```

### 8.6 提交风险

以下情况均弹出确认提示，但不阻止保存：

| 情况                     | 等级 | 保存后的处理               |
| ------------------------ | ---- | -------------------------- |
| 计划工时超过排班时间段   | 红色 | 保存后持续标记超时风险     |
| 计划工时未占满排班时间段 | 黄色 | 允许确认保存，显示剩余时间 |
| 商品当日模具产能超出     | 红色 | 日历和订单持续标记产能风险 |
| 任务超出最晚完成制作日期 | 红色 | 订单持续标记交期风险       |

确认保存时保留风险代码、确认时间和操作记录。

### 8.7 缺勤和请假

排班不做无痕删除，支持状态：

```text
待确认、已到岗、迟到、请假、缺勤、取消、已完成
```

兼职临时不来时：

1. 将 Shift 标记为请假或缺勤；
2. 对应 ShiftTask 标记为待补排；
3. 释放该时段人工工时和商品当天的计划产量占用；
4. 重新计算订单未完成数量和交期风险；
5. 在日历中提示管理员重新安排人员或日期。

## 9. 实际生产、人工成本和提成

排班结束后，任务可登记：

```text
实际开始和结束时间、实际任务工时
合格完成数量、返工数量、报废数量、备注
```

```text
实际人工时薪成本 = 实际任务工时 × 兼职人员时薪
实际提成 = 合格完成数量 × 商品单件提成快照
订单商品完成率 = 合格完成数量 ÷ 订单商品数量
```

订单所有商品明细满足完成条件后，系统建议进入待发货；管理员保留手动调整订单状态的能力。

## 10. 本地后端架构

### 10.1 总体结构

第一期不启动独立 HTTP 服务。Electron Main 承担本地业务后端职责：

```text
React 桌面界面
  ↓ 受限 API 调用
Preload / IPC 契约层
  ↓
Electron Main 本地后端
  ├─ 领域服务：订单、排班、成本、收付款、报表
  ├─ 数据仓储：SQLite
  ├─ 文件服务：商品图片和付款凭证
  └─ 备份、恢复、导入导出、操作日志
```

### 10.2 分层目录

```text
src/
  main/
    bootstrap/
    ipc/
    modules/
    database/
    repositories/
    services/
    files/
    backup/
    audit/
  preload/
  renderer/
    app/
    pages/
    features/
    components/
    design-system/
    stores/
    services/
    types/
```

职责：

```text
renderer：页面、日历、表格、交互和状态展示
preload：受限桌面 API
main/services：订单、排班、成本、备份等业务规则
main/repositories：SQLite 读写和事务
```

### 10.3 业务模块

| 模块       | 服务职责                                       |
| ---------- | ---------------------------------------------- |
| catalog    | 商品资料、价格、成本参数、模具产能             |
| orders     | 客户、订单、订单商品、发货日期与快照           |
| payments   | 多次收款、退款、余额和凭证                     |
| scheduling | 排班、时间冲突、工时、模具产能、交期风险、补排 |
| production | 到岗、缺勤、实际完成、人工工时和提成           |
| analytics  | 成本、利润、工时、提成、收付款和风险报表       |
| backup     | 数据库备份、恢复、导出与导入                   |
| audit      | 改价、收退款、排班确认、恢复等关键操作记录     |

### 10.4 领域服务规则

- 前端可做即时预览，但订单成本、模具日产能、交期风险和收款余额必须由 Main 端重新计算；
- 订单、收退款、排班、实际完成等跨表修改使用 SQLite 事务；
- 商品价格和成本参数在订单商品中保存快照；
- 模具数量和每日批次数属于现实物理产能，未完成订单排产时读取商品当前配置；
- 确认风险保存后，后端写入风险代码、确认时间和操作记录。

### 10.5 IPC 契约

不暴露通用数据库操作，只暴露业务能力：

```text
orders.create(input)
orders.getDetail(orderId)
orders.addPayment(input)
orders.addRefund(input)

schedule.getCalendar(range, filters)
schedule.previewShift(input)
schedule.saveShift(input, confirmedWarningCodes)
schedule.markAbsent(shiftId, reason)

production.completeShiftTask(input)
backup.create()
backup.restore(filePath)
export.orders(filters)
```

主进程校验参数完整性、金额合法性、订单状态、时间范围、任务归属和人员冲突。

## 11. 本地数据、备份和恢复

```text
SQLite 数据库：应用数据目录
商品图片和付款凭证：应用数据目录附件目录
备份包：数据库和附件清单
```

功能：

- 手动立即备份；
- 启动或退出时自动备份；
- 保留最近若干份备份；
- 导出完整备份包；
- 从备份包恢复；
- 订单、商品、人员、收付款导出 Excel。

恢复前自动创建当前数据备份，并要求二次确认，避免误覆盖。

## 12. 后续多端扩展

第一期领域服务不依赖页面组件或 IPC 实现。未来需要多电脑共享时：

```text
React 页面
→ 从 window.yumi.xxx() 替换为 HTTP API Client
→ 复用 OrderService、ScheduleService、CostCalculator 等领域服务
→ SQLite 迁移至 PostgreSQL
→ 增加账号、权限、同步和云端审计
```

第一期不为云端协作额外引入复杂度，但保持业务层可迁移。

## 13. 分阶段实施顺序

### 阶段一：基础资料、订单和数据安全

1. 初始化 Electron 本地项目与设计系统；
2. 商品、兼职人员、客户档案；
3. 订单、订单商品、多次收款与退款；
4. 价格、成本、缝边、发货与预留时间；
5. SQLite 迁移、备份和基础导出。

### 阶段二：日历排班和生产执行

1. 周历与月历排班；
2. 上班时间段、订单商品任务和计划数量；
3. 工时、模具日产能和交期风险提示；
4. 请假、缺勤、取消和待补排；
5. 实际完成、人工成本和按件提成。

### 阶段三：报表和效率体验

1. 订单利润、收款、退款和待收款报表；
2. 商品成本和售价分析；
3. 人员工时、提成、出勤和完成件数；
4. 高级筛选、批量操作、快捷键和导出；
5. 评估自动批次推算和多端同步扩展。

## 14. 验收标准

| 能力     | 验收结果                                                     |
| -------- | ------------------------------------------------------------ |
| 商品成本 | 可按重量、损耗、胶水单价、包装、工时、提成和固定成本预估成本 |
| 缝边     | 不同商品配置不同缝边单价，订单可选并单独计费                 |
| 多次付款 | 一笔订单可多次收款和退款，自动计算待收金额                   |
| 发货风险 | 可设置预计发货和预留天数，计算最晚制作完成日期               |
| 日历排班 | 可直接创建兼职人员日期和起止时间排班                         |
| 任务归属 | 每个排班任务必须关联订单商品和计划数量                       |
| 模具限制 | 能识别并提示商品每日模具和批次产能超出                       |
| 异常处理 | 缺勤后任务进入待补排，人工和模具占用重新计算                 |
| 结算     | 实际完成数量决定固定单件提成，实际任务工时决定时薪成本       |
| 数据安全 | 能完成本地备份、恢复与业务数据导出                           |
