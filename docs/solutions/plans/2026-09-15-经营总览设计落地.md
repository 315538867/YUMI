# 经营总览设计落地 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `openspec-delivery` to implement this plan
> through OpenSpec after explicit authorization. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将经营报表从表格优先改造成以真实现金经营结果为主叙事的经营总览，让负责人快速理解实际收入、经营支出、经营结果，以及工资和其他经营支出的占比，同时保留原有明细核对能力。

**Architecture:** 仅在 renderer 展示层增加财务总览模型与组件，复用现有 `V2MonthlyOperationReport`。月度主视图严格使用实际收付款口径；工资使用已确认并实际发放金额；其他经营支出仅作为经营支出扣除已确认工资后的余额，并在页面明确说明。订单核算、排班、产能、交期和工资表格继续作为二级核对入口，不与现金经营结果混算。

**Tech Stack:** React 19, TypeScript, Vitest, Testing Library, 现有 YUMI UI 组件与 CSS variables。

---

## Implementation Tasks

- [x] 为经营总览金额和比例计算编写纯函数测试，覆盖正常、零收入和工资异常口径。
- [x] 实现经营总览展示组件，使用“收入 − 支出 = 结果”的账本式结构，显示收入基准、支出占收入、结果占收入和工资 / 其他支出构成占比。
- [x] 将经营总览接入经营报表页面，保留月份筛选、刷新、导出和现有数据来源。
- [x] 将原有明细表格归入“需要核对时”层级，保持风险导航、导出菜单和表格无数据状态。
- [x] 补充页面级测试，验证首屏信息层级、财务口径说明、金额占比和零值展示。
